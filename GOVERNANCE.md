# Project Governance

## Governance Model

Pantoken is currently maintained using a **Benevolent Dictator for Life (BDFL)** governance model.

The project maintainer is responsible for the overall direction of the project, including:

- Reviewing and merging pull requests.
- Approving or rejecting new features.
- Making release decisions.
- Resolving technical disagreements.
- Maintaining project security and quality standards.

## Contributions

Contributions are welcome through GitHub pull requests and issues.

All contributions are reviewed before being merged. Review considers:

- Correctness
- Security
- Backward compatibility
- Code quality
- Test coverage
- Documentation

Submitting a pull request does not guarantee it will be merged.

## Decision Making

Technical decisions are made through discussion in GitHub issues and pull requests whenever practical.

When consensus cannot be reached, the project maintainer makes the final decision.

## Roles and Responsibilities

### Project Maintainer

The Project Maintainer is responsible for the overall health and direction of the project.

Responsibilities include:

- Reviewing and merging pull requests.
- Reviewing and triaging issues.
- Planning and approving new features.
- Making release decisions.
- Maintaining project documentation.
- Responding to security reports.
- Managing project dependencies.
- Ensuring automated tests and continuous integration remain operational.
- Making final decisions when consensus cannot be reached.

Current Project Maintainer:

- Danny Wahl (@thedannywahl)

### Contributors

Anyone may contribute to the project by submitting issues, pull requests, documentation improvements, or other enhancements.

Contributors are responsible for:

- Following the project's contribution guidelines.
- Ensuring contributions are their own work and comply with the project's licensing requirements.
- Including appropriate tests and documentation where applicable.
- Responding to review feedback.

### Users

Users are encouraged to:

- Report bugs.
- Request features.
- Participate in technical discussions.
- Provide feedback on releases.

Users do not have commit or release privileges unless they are also maintainers.

## Project Continuity

### Goal

Pantoken is intended to remain maintainable even if the current maintainer becomes unavailable due to death, incapacity, or other long-term absence.

### Repository Access

The project source code, issue tracker, release history, and documentation are hosted publicly on GitHub.

If the maintainer becomes permanently unavailable, a designated trusted individual will be granted ownership or administrative access to the repository as soon as practical.

### Credentials

The following credentials and assets required to maintain the project are documented and stored in an encrypted password manager with emergency-access provisions:

- GitHub account recovery information
- npm publishing credentials (if applicable)
- Domain registration credentials (if applicable)
- Code signing keys (if applicable)

### Transfer of Responsibility

The designated successor will have access to the information necessary to:

- Review and merge pull requests.
- Create and close issues.
- Publish new releases.
- Rotate credentials if necessary.
- Add or remove maintainers.

The goal is to restore normal project maintenance within one week of confirming that the original maintainer can no longer support the project.

### Open Source Rights

The project is licensed under an OSI-approved open source license. The repository history and documentation remain publicly available so that maintenance may continue by successor maintainers or the community if necessary.

# Zgodność

<!-- Wygenerowano przez `vp run sync:compatibility`. Nie edytuj ręcznie; uruchom generator i zatwierdź zmiany. -->

Ta strona dokumentuje źródła Instructure UI, z których korzysta kompilacja pantoken, oraz odbiorców, którzy z nich korzystają. Wersje docelowe są rozpatrywane osobno: uwzględniono wyłącznie zweryfikowane wydania, a wydania nowsze niż ostatnie zweryfikowane wymagają przeglądu. Wygeneruj stronę ponownie za pomocą `vp run sync:compatibility`; kontrola `gate:compatibility` zgłasza błąd, jeśli zawartość ulegnie zmianie.

## Przegląd wydań docelowych

Cotygodniowy workflow monitorujący wydania docelowe tworzy zgłoszenie przeglądu dla nowych stabilnych wydań WordPressa oraz ekosystemów z jawnym npm peer. W przypadku pozostałych celów opiekunowie co tydzień sprawdzają oficjalne informacje o wydaniach platformy i ręcznie tworzą zgłoszenie przeglądu; brak zgłoszenia nie oznacza, że obsługiwane jest nowe wydanie. Aby rozszerzyć deklarowaną obsługę:

1. Sprawdź schemat wyjściowy wydania lub zmiany integracyjne oraz adapter z tej tabeli.
2. Uruchom polecenie sprawdzające zgodność adaptera z kandydackim wydaniem, na przykład `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. Domyślne polecenie odczytuje każdy wpis `testedVersions` z tego rejestru; sparowane środowiska akceptują towarzyszące im flagi.
3. W przypadku kandydatów wykrytych na podstawie kanałów informacyjnych użyj `vp run downstream:test`; nieudane próby są zachowywane w `scripts/release/downstream-compatibility.json`. Po pomyślnym przeglądzie uruchom `vp run downstream:bless --package @pantoken/name --version x.y.z`, aby zaktualizować deklarowaną obsługę.
4. Uruchom test z rzeczywistym hostem, kompilatorem lub narzędziem do kompilacji dla wersji minimalnej i nowego wydania. W razie potrzeby dostosuj bieżący format wyjściowy; nie dodawaj równoległych generatorów przestarzałych formatów.
5. Zaktualizuj `scripts/release/target-compatibility.json` dopiero po pomyślnym przejściu kontroli, a następnie uruchom `vp run sync:compatibility`, ponownie wygeneruj angielską dokumentację API i dodaj changeset. Nowsze wydania pozostają w oczekiwaniu do czasu włączenia tej zmiany po przeglądzie. Dokumentacja lokalizowana jest obsługiwana osobno.

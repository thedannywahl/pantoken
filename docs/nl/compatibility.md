Deze pagina legt vast van welke Instructure UI-bronnen deze pantoken-build gebruikmaakt en welke consumers deze gebruiken. Doelversies staan los van elkaar: alleen geverifieerde releases worden vermeld; releases die nieuwer zijn dan de laatst geverifieerde release moeten worden beoordeeld. Genereer de pagina opnieuw met `vp run sync:compatibility`; de controle `gate:compatibility` faalt als de pagina afwijkt.

## Doelreleases beoordelen

De wekelijkse workflow voor doelreleases opent een issue ter beoordeling van nieuwe stabiele WordPress-releases en ecosystemen met een expliciete npm-peerdependency. Voor andere doelen controleren maintainers wekelijks de officiële release-opmerkingen van het platform en openen ze handmatig een issue ter beoordeling; het ontbreken van een issue betekent niet dat een nieuwe release wordt ondersteund. Een claim uitbreiden:

1. Bekijk de uitvoerschema's of integratiewijzigingen van de release en de adapter in deze tabel.
2. Voer de compatibiliteitsopdracht van de adapter uit met de kandidaat-release, bijvoorbeeld `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. De standaardopdracht leest elke `testedVersions`-vermelding uit dit register; gekoppelde omgevingen accepteren de bijbehorende flags.
3. Gebruik voor kandidaten die via feeds zijn ontdekt `vp run downstream:test`; mislukte pogingen worden bewaard in `scripts/release/downstream-compatibility.json`. Voer na een geslaagde beoordeling `vp run downstream:bless --package @pantoken/name --version x.y.z` uit om de claim bij te werken.
4. Voer een controle uit met de daadwerkelijke host, compiler of buildtool voor zowel de minimumversie als de nieuwe release. Pas indien nodig de huidige uitvoerindeling aan; voeg geen parallelle emitters voor verouderde indelingen toe.
5. Werk `scripts/release/target-compatibility.json` pas bij nadat de controles zijn geslaagd, voer vervolgens `vp run sync:compatibility` uit, genereer de Engelse API-documentatie opnieuw en voeg een changeset toe. Nieuwere releases blijven in afwachting totdat die beoordeelde wijziging is doorgevoerd. Gelokaliseerde documentatie wordt afzonderlijk bijgewerkt.

## Verouderde tokens

Tokens die upstream zijn verwijderd maar die pantoken nog als compatibiliteitsshim levert. Elke token blijft werken totdat de upstream-minorversie `Removed in` wordt overgenomen; daarna wordt de shim verwijderd en verschijnt er een minorversie voor consumers. Een shim verwijst door naar een token van `Replacement` of bevriest de laatst bekende waarde.

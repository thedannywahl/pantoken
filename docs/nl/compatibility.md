Deze pagina legt vast uit welke Instructure UI-bronnen deze pantoken-build gegevens haalt en welke consumers ze gebruiken. Doelversies worden afzonderlijk bijgehouden: alleen geverifieerde releases worden vermeld, en releases nieuwer dan de laatst geverifieerde release moeten worden beoordeeld. Genereer de pagina opnieuw met `vp run sync:compatibility`; de controle `gate:compatibility` mislukt als de pagina afwijkt.

## Doelreleases beoordelen

De wekelijkse workflow voor doelreleases opent een beoordelingsissue voor nieuwe stabiele WordPress-releases en ecosystemen met een expliciete npm-peerdependency. Voor andere doelen controleren maintainers wekelijks de officiële releaseopmerkingen van het platform en openen ze handmatig een beoordelingsissue; het ontbreken van een issue betekent niet dat een nieuwe release wordt ondersteund. Zo breid je een claim uit:

1. Bekijk het uitvoerschema of de integratiewijzigingen van de release en de adapter in deze tabel.
2. Voer de compatibiliteitsopdracht van de adapter uit met de kandidaat-release, bijvoorbeeld `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. De standaardopdracht leest elk `testedVersions`-item uit dit register; voor gekoppelde omgevingen zijn de bijbehorende flags beschikbaar.
3. Gebruik voor kandidaten die via feeds zijn ontdekt `vp run downstream:test`; mislukte pogingen worden bewaard in `scripts/release/downstream-compatibility.json`. Voer na een geslaagde beoordeling `vp run downstream:bless --package @pantoken/name --version x.y.z` uit om de claim bij te werken.
4. Voer een controle uit met de echte host, compiler of buildtool voor zowel de minimumversie als de nieuwe release. Pas zo nodig de huidige uitvoerindeling aan; voeg geen parallelle emitters voor oude indelingen toe.
5. Werk `scripts/release/target-compatibility.json` pas bij nadat de controles zijn geslaagd, voer vervolgens `vp run sync:compatibility` uit, genereer de Engelse API-documentatie opnieuw en voeg een changeset toe. Nieuwere releases blijven in afwachting totdat die beoordeelde wijziging is opgenomen. Gelokaliseerde documentatie wordt afzonderlijk afgehandeld.

## Verouderde tokens

Tokens die upstream zijn verwijderd, maar die pantoken nog als compatibiliteitsshims levert. Elke shim blijft werken totdat de upstream-minorversie `Removed in` wordt overgenomen; daarna wordt de shim buiten gebruik gesteld en wordt een minorversie van de consumer uitgebracht.

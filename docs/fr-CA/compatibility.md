Cette page consigne les sources de l’interface utilisateur Instructure à partir desquelles cette compilation de pantoken effectue la résolution, ainsi que les consommateurs qui les utilisent. Les versions cibles sont distinctes : seules les versions vérifiées sont indiquées, et les versions plus récentes que la dernière version vérifiée doivent être examinées. Régénérez cette page avec `vp run sync:compatibility`; la vérification `gate:compatibility` échoue si le contenu diffère.

## Examiner les versions cibles

Le flux de travail hebdomadaire sur les versions cibles ouvre un ticket d’examen pour les nouvelles versions stables de WordPress et les écosystèmes ayant une dépendance npm explicite. Pour les autres cibles, les responsables vérifient chaque semaine les notes de version officielles de la plateforme et ouvrent manuellement un ticket d’examen; l’absence d’un ticket ne signifie pas qu’une nouvelle version est prise en charge. Pour élargir une affirmation :

1. Examinez le schéma de sortie de la version ou les changements d’intégration, ainsi que l’adaptateur de ce tableau.
2. Exécutez la commande de compatibilité de l’adaptateur avec la version candidate, par exemple
   `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. La commande par défaut lit chaque entrée
   `testedVersions` de ce registre; les environnements jumelés acceptent leurs options complémentaires.
3. Pour les versions candidates découvertes dans les flux, utilisez `vp run downstream:test`; les tentatives échouées sont conservées dans
   `scripts/release/downstream-compatibility.json`. Après un examen réussi, exécutez
   `vp run downstream:bless --package @pantoken/name --version x.y.z` pour mettre à jour l’affirmation.
4. Effectuez une vérification avec un véritable hôte, compilateur ou outil de compilation à la version minimale et à la nouvelle version. Remappez le format de sortie actuel au besoin; n’ajoutez pas d’émetteurs parallèles de formats hérités.
5. Mettez à jour `scripts/release/target-compatibility.json` seulement une fois les vérifications réussies, puis exécutez
   `vp run sync:compatibility`, régénérez la documentation API en anglais et ajoutez un changeset. Les versions plus récentes restent en attente jusqu’à ce que le changement examiné soit intégré. La documentation localisée est traitée séparément.

## Dépréciations

Jetons supprimés en amont que pantoken continue de fournir sous forme de mécanisme de compatibilité. Chacun demeure fonctionnel jusqu’à l’adoption de la version mineure en amont `Removed in`; le mécanisme est alors retiré et une version mineure du consommateur est publiée. Un mécanisme de compatibilité redirige vers un jeton `Replacement` ou conserve sa dernière valeur connue.

Esta página registra as fontes da Instructure UI das quais esta compilação do pantoken resolve dados e quais consumidores as utilizam. As versões-alvo são independentes: somente versões verificadas são declaradas, e versões posteriores à última versão verificada precisam ser revisadas. Gere novamente com `vp run sync:compatibility`; a verificação `gate:compatibility` falha se houver divergências.

## Revisão de versões-alvo

O fluxo de trabalho semanal de versões-alvo abre uma issue de revisão para novas versões estáveis do WordPress e ecossistemas com um peer explícito do npm. Para os demais alvos, os mantenedores verificam semanalmente as notas oficiais de versão da plataforma e abrem uma issue de revisão manualmente; a ausência de uma issue não significa que uma nova versão seja compatível. Para ampliar uma declaração:

1. Inspecione o esquema de saída da versão ou as alterações de integração e o adaptador nesta tabela.
2. Execute o comando de compatibilidade do adaptador com a versão candidata, por exemplo, `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. O comando padrão lê todas as entradas `testedVersions` deste registro; ambientes pareados aceitam as respectivas flags complementares.
3. Para candidatos descobertos pelo feed, use `vp run downstream:test`; tentativas malsucedidas são mantidas em `scripts/release/downstream-compatibility.json`. Após uma revisão bem-sucedida, execute `vp run downstream:bless --package @pantoken/name --version x.y.z` para atualizar a declaração.
4. Execute uma verificação com o ambiente real, compilador ou ferramenta de compilação na versão mínima e na nova versão. Se necessário, mapeie novamente o formato de saída atual; não adicione emissores paralelos de formatos legados.
5. Atualize `scripts/release/target-compatibility.json` somente depois que as verificações forem aprovadas; em seguida, execute `vp run sync:compatibility`, gere novamente a documentação da API em inglês e adicione um changeset. As versões mais recentes permanecem pendentes até que essa alteração revisada seja integrada. A documentação localizada é tratada separadamente.

## Descontinuações

Tokens removidos do upstream que o pantoken ainda fornece como camada de compatibilidade. Cada um continua funcionando até que a versão minor upstream `Removed in` seja adotada; nesse momento, a camada de compatibilidade é retirada e uma versão minor do consumidor é publicada. A camada encaminha para um token `Replacement` ou mantém fixo seu último valor conhecido.

Esta página registra as fontes do Instructure UI das quais esta compilação do pantoken resolve informações e quais
consumidores as utilizam. As versões-alvo são separadas: somente versões verificadas são consideradas válidas, e
versões mais recentes que a última versão verificada precisam de revisão. Regenere-a com `vp run sync:compatibility`; a
verificação `gate:compatibility` falha caso ela fique desatualizada.

## Revisão das versões-alvo

O fluxo semanal de versões-alvo abre uma issue de revisão para novas versões estáveis do WordPress e
para ecossistemas com um peer npm explícito. Para os demais alvos, os mantenedores verificam as notas oficiais de
versão da plataforma semanalmente e abrem uma issue de revisão manualmente; a ausência de uma issue não significa que uma nova
versão seja suportada. Para ampliar uma declaração:

1. Inspecione o esquema de saída da versão ou as alterações na integração e o adaptador nesta tabela.
2. Execute o comando de compatibilidade do adaptador com a versão candidata, por exemplo
   `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. O comando padrão lê todas as
   entradas `testedVersions` deste registro; os ambientes emparelhados aceitam suas flags complementares.
3. Para candidatos descobertos por feed, use `vp run downstream:test`; as tentativas com falha são mantidas em
   `scripts/release/downstream-compatibility.json`. Após uma revisão bem-sucedida, execute
   `vp run downstream:bless --package @pantoken/name --version x.y.z` para atualizar a declaração.
4. Execute uma verificação real em host, compilador ou ferramenta de build na versão mínima e na nova versão. Remapeie o formato de
   saída atual se necessário; não adicione emitters paralelos em formato legado.
5. Atualize `scripts/release/target-compatibility.json` somente após as verificações serem aprovadas, depois execute
   `vp run sync:compatibility`, regenere a documentação da API em inglês e adicione um changeset. Versões mais novas
   permanecem pendentes até que essa alteração revisada seja aplicada. A documentação localizada é tratada separadamente.

## Depreciações

Tokens removidos pelo upstream que o pantoken ainda disponibiliza como shim de compatibilidade. Cada um continua funcionando até
que sua versão menor upstream `Removed in` seja adotada, momento em que o shim é retirado e uma versão menor
do consumidor é criada. Um shim encaminha para um token `Replacement` ou congela seu último valor conhecido.

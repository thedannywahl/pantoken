이 페이지에는 이 pantoken 빌드가 해석해 사용하는 Instructure UI 소스와 이를 사용하는 소비자가 기록되어 있습니다. 대상별 버전은 별도로 관리합니다. 검증된 릴리스만 명시하며, 마지막으로 검증한 릴리스보다 최신인 릴리스는 검토가 필요합니다. `vp run sync:compatibility`을(를) 사용해 다시 생성하세요. `gate:compatibility` 검사에서 내용이 어긋나면 실패합니다.

## 대상 릴리스 검토

주간 대상 릴리스 워크플로는 새로운 안정 버전의 WordPress 릴리스와 명시적인 npm 피어 종속성이 있는 생태계를 대상으로 검토 이슈를 엽니다. 그 밖의 대상은 유지 관리자가 플랫폼의 공식 릴리스 노트를 매주 확인하고 수동으로 검토 이슈를 열어야 합니다. 이슈가 없다고 해서 새 릴리스가 지원되는 것은 아닙니다. 지원 주장을 확장하려면 다음을 수행하세요.

1. 해당 릴리스의 출력 스키마 또는 통합 변경 사항과 이 표의 어댑터를 검사합니다.
2. 후보 릴리스를 지정해 어댑터의 호환성 명령을 실행합니다. 예: `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. 기본 명령은 이 레지스트리의 모든 `testedVersions` 항목을 읽습니다. 쌍을 이루는 환경에서는 함께 사용하는 플래그를 지정할 수 있습니다.
3. 피드에서 발견한 후보에는 `vp run downstream:test`을(를) 사용합니다. 실패한 시도는 `scripts/release/downstream-compatibility.json`에 보존됩니다. 검토가 성공하면 `vp run downstream:bless --package @pantoken/name --version x.y.z`을(를) 실행해 지원 주장을 갱신합니다.
4. 최소 버전과 새 릴리스 버전에서 실제 호스트, 컴파일러 또는 빌드 도구 검사를 수행합니다. 필요한 경우 현재 출력 형식을 다시 매핑하고, 병렬 레거시 형식 출력기를 추가하지 마세요.
5. 검사가 통과한 뒤에만 `scripts/release/target-compatibility.json`을(를) 업데이트하고, `vp run sync:compatibility`을(를) 실행해 영어 API 문서를 다시 생성한 후 변경 사항을 추가합니다. 더 최신 릴리스는 검토된 변경 사항이 반영될 때까지 대기 상태로 둡니다. 현지화된 문서는 별도로 처리합니다.

## 사용 중단

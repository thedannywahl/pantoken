# 호환성

<!-- `vp run sync:compatibility`에서 생성됨. 직접 편집하지 마세요. 작성기를 실행하고 커밋하세요. -->

이 페이지에는 이 pantoken 빌드가 확인하는 Instructure UI 소스와 이를 사용하는 소비자가 기록되어 있습니다. 대상 버전은 서로 별개입니다. 검증된 릴리스만 명시하며, 마지막으로 검증된 릴리스보다 최신인 릴리스는 검토가 필요합니다. `vp run sync:compatibility`로 다시 생성하세요. 버전이 달라지면 `gate:compatibility` 검사에서 실패합니다.

## 타깃 릴리스 검토

주간 타깃 릴리스 워크플로는 새로운 안정 버전의 WordPress와 명시적인 npm 피어가 있는 생태계에 대한 검토 이슈를 엽니다. 다른 타깃은 유지관리자가 플랫폼의 공식 릴리스 노트를 매주 확인하고 수동으로 검토 이슈를 엽니다. 이슈가 없다고 해서 새 릴리스가 지원되는 것은 아닙니다. 지원 주장을 확장하려면 다음 단계를 따르세요.

1. 릴리스의 출력 스키마 또는 통합 변경 사항과 이 표의 어댑터를 살펴봅니다.
2. 후보 릴리스를 사용해 어댑터의 호환성 명령을 실행합니다. 예를 들면 다음과 같습니다.
   `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. 기본 명령은 이 레지스트리의 모든 `testedVersions` 항목을 읽습니다. 쌍을 이루는 환경에서는 동반 플래그를 사용할 수 있습니다.
3. 피드에서 발견된 후보에는 `vp run downstream:test`을 사용합니다. 실패한 시도는 `scripts/release/downstream-compatibility.json`에 보존됩니다. 검토가 성공하면 `vp run downstream:bless --package @pantoken/name --version x.y.z`를 실행해 지원 주장을 업데이트합니다.
4. 최소 버전과 새 릴리스에서 실제 호스트, 컴파일러 또는 빌드 도구 검사를 수행합니다. 필요한 경우 현재 출력 형식을 다시 매핑하고, 기존 형식 출력을 병렬로 추가하지 마세요.
5. 검사를 통과한 뒤에만 `scripts/release/target-compatibility.json`을 업데이트합니다. 그런 다음 `vp run sync:compatibility`을 실행하고, 영어 API 문서를 다시 생성한 후 변경 기록을 추가합니다. 검토된 변경 사항이 반영될 때까지 더 최신 릴리스는 보류 상태로 유지됩니다. 현지화된 문서는 별도로 처리합니다.

## 사용 중단

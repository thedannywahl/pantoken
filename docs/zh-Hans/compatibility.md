## 审核目标版本

每周目标版本工作流会为新的稳定版 WordPress 发布版本以及具有明确 npm peer 的生态系统创建审核 issue。对于其他目标，维护者每周检查平台的官方发布说明，并手动创建审核 issue；没有 issue 并不意味着支持新版本。要扩展兼容性声明：

1. 检查该版本的输出架构或集成变更，以及此表中的适配器。
2. 使用候选版本运行适配器的兼容性命令，例如 `vp run @pantoken/postcss#check:compatibility -- 8.5.29`。默认命令会读取此注册表中的每个 `testedVersions` 条目；成对的环境可以接受对应的配套标志。
3. 对于通过源发现的候选版本，使用 `vp run downstream:test`；失败的尝试会保留在 `scripts/release/downstream-compatibility.json` 中。审核成功后，运行 `vp run downstream:bless --package @pantoken/name --version x.y.z` 更新兼容性声明。
4. 在最低版本和新版本上运行真实宿主、编译器或构建工具检查。如有需要，重新映射当前输出格式；不要添加并行的旧格式生成器。
5. 只有检查通过后才更新 `scripts/release/target-compatibility.json`，然后运行 `vp run sync:compatibility`、重新生成英文 API 文档，并添加 changeset。审核变更合并前，较新的版本仍处于待处理状态。本地化文档另行处理。

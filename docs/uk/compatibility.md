# Сумісність

<!-- Створено за допомогою `vp run sync:compatibility`. Не редагуйте вручну; запустіть генератор і створіть коміт. -->

На цій сторінці зафіксовано джерела Instructure UI, з яких pantoken отримує дані під час збирання, і споживачів, які їх використовують. Цільові версії наведено окремо: вказано лише перевірені випуски, а випуски новіші за останній перевірений потребують перевірки. Оновіть сторінку за допомогою `vp run sync:compatibility`; перевірка `gate:compatibility` завершується помилкою, якщо дані застаріли.

## Перевірка цільових випусків

Щотижневий робочий процес перевірки цільових випусків створює запит на перевірку для нових стабільних випусків WordPress та екосистем із явно зазначеним npm peer. Для інших цільових платформ супровідники щотижня перевіряють офіційні примітки до випусків платформи та створюють запит на перевірку вручну; відсутність запиту не означає, що підтримується новий випуск. Щоб розширити твердження:

1. Перевірте схему вихідних даних випуску або зміни інтеграції, а також адаптер у цій таблиці.
2. Запустіть команду перевірки сумісності адаптера з кандидатом на випуск, наприклад `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. За замовчуванням команда читає всі записи `testedVersions` з цього реєстру; для парних середовищ передбачено додаткові прапорці.
3. Для кандидатів, знайдених каналом оновлень, використовуйте `vp run downstream:test`; невдалі спроби зберігаються в `scripts/release/downstream-compatibility.json`. Після успішної перевірки запустіть `vp run downstream:bless --package @pantoken/name --version x.y.z`, щоб оновити твердження.
4. Перевірте мінімальний і новий випуски у справжньому середовищі хоста, компіляторі або засобі збирання. За потреби змініть поточний формат виводу; не додавайте паралельні генератори застарілих форматів.
5. Оновіть `scripts/release/target-compatibility.json` лише після успішного проходження перевірок, а потім запустіть `vp run sync:compatibility`, згенеруйте англійську документацію API та додайте changeset. Новіші випуски залишаються на розгляді, доки відповідна зміна не потрапить до основної гілки. Локалізована документація оновлюється окремо.

## Застарілі токени

Токени, від яких upstream відмовився, але які pantoken досі постачає як shim для сумісності. Кожен із них продовжує працювати до впровадження upstream minor-випуску `Removed in`; після цього shim вилучається, а для споживача готується minor-випуск. Shim або перенаправляє на токен `Replacement`, або фіксує його останнє відоме значення.

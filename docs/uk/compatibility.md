# Сумісність

<!-- Згенеровано за допомогою `vp run sync:compatibility`. Не редагуйте вручну; запустіть генератор і зафіксуйте зміни. -->

На цій сторінці зазначено джерела Instructure UI, з яких ця збірка pantoken отримує дані, а також споживачів, які їх використовують. Цільові версії розглядаються окремо: вказуються лише перевірені випуски, а випуски новіші за останній перевірений потребують перегляду. Згенеруйте сторінку повторно за допомогою `vp run sync:compatibility`; перевірка `gate:compatibility` завершується помилкою, якщо вміст сторінки не відповідає джерелу.

## Перегляд цільових випусків

Щотижневий процес перевірки цільових випусків створює запит на перегляд нових стабільних випусків WordPress та екосистем із явно зазначеною npm peer-залежністю. Для інших цільових платформ супроводжувачі щотижня перевіряють офіційні примітки до випусків платформи та вручну створюють запит на перегляд; відсутність запиту не означає, що підтримується новий випуск. Щоб розширити заявлений діапазон:

1. Перевірте схему виводу випуску або зміни інтеграції, а також адаптер у цій таблиці.
2. Запустіть команду перевірки сумісності адаптера з кандидатом на випуск, наприклад
   `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. За замовчуванням команда читає кожен запис
   `testedVersions` із цього реєстру; для парних середовищ передаються відповідні прапорці.
3. Для кандидатів, виявлених через стрічку, скористайтеся `vp run downstream:test`; невдалі спроби зберігаються в
   `scripts/release/downstream-compatibility.json`. Після успішного перегляду запустіть
   `vp run downstream:bless --package @pantoken/name --version x.y.z`, щоб оновити заявлений діапазон.
4. Перевірте роботу на мінімальному та новому випусках у реальному середовищі, компіляторі або засобі збірки. За потреби змініть поточний формат виводу; не додавайте паралельні генератори застарілого формату.
5. Оновлюйте `scripts/release/target-compatibility.json` лише після успішного проходження перевірок, а потім запустіть
   `vp run sync:compatibility`, згенеруйте англійську документацію API та додайте changeset. Новіші випуски залишаються непідтвердженими, доки відповідна зміна після перегляду не буде включена. Локалізована документація ведеться окремо.

## Застарілі токени

Кожен із них продовжує працювати до прийняття upstream-випуску `Removed in`, після чого шим вилучається, а для споживача готується мінорний випуск.

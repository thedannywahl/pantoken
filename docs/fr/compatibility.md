Cette page répertorie les sources d’Instructure UI à partir desquelles cette version de pantoken résout les données, ainsi que les consommateurs qui les utilisent. Les versions cibles sont distinctes : seules les versions vérifiées sont indiquées, et les versions plus récentes que la dernière version vérifiée doivent être examinées. Régénérez cette page avec `vp run sync:compatibility` ; la vérification `gate:compatibility` échoue si le contenu diffère.

## Examiner les versions cibles

Le flux de travail hebdomadaire de vérification des versions cibles ouvre un ticket d’examen pour les nouvelles versions stables de WordPress et les écosystèmes ayant une dépendance npm peer explicite. Pour les autres cibles, les responsables vérifient chaque semaine les notes de version officielles de la plateforme et ouvrent manuellement un ticket d’examen ; l’absence de ticket ne signifie pas qu’une nouvelle version est prise en charge. Pour étendre une déclaration :

1. Examinez le schéma de sortie de la version ou les changements d’intégration, ainsi que l’adaptateur indiqué dans ce tableau.
2. Exécutez la commande de compatibilité de l’adaptateur avec la version candidate, par exemple `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. La commande par défaut lit chaque entrée `testedVersions` de ce registre ; les environnements jumelés acceptent leurs options correspondantes.
3. Pour les versions candidates détectées par le flux, utilisez `vp run downstream:test` ; les tentatives échouées sont conservées dans `scripts/release/downstream-compatibility.json`. Après une vérification réussie, exécutez `vp run downstream:bless --package @pantoken/name --version x.y.z` pour mettre à jour la déclaration.
4. Effectuez une vérification avec un véritable hôte, compilateur ou outil de build, sur la version minimale et la nouvelle version. Adaptez le format de sortie actuel si nécessaire ; n’ajoutez pas d’émetteurs parallèles pour les anciens formats.
5. Mettez à jour `scripts/release/target-compatibility.json` uniquement après la réussite des vérifications, puis exécutez `vp run sync:compatibility`, régénérez la documentation API en anglais et ajoutez un changeset. Les versions plus récentes restent en attente jusqu’à la fusion de cette modification vérifiée. La documentation localisée est traitée séparément.

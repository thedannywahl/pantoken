## 檢視目標版本

每週的目標版本工作流程會針對新的 WordPress 穩定版本，以及明確設定 npm peer 的生態系統，建立檢視問題。對於其他目標，維護者每週檢查平台的官方版本資訊，並手動建立檢視問題；沒有問題不代表支援新版本。若要擴大支援聲明：

1. 檢查該版本的輸出結構描述或整合變更，以及本表中的介接器。
2. 使用候選版本執行介接器的相容性命令，例如 `vp run @pantoken/postcss#check:compatibility -- 8.5.29`。預設命令會讀取此登錄檔中的每個 `testedVersions` 項目；成對的環境可使用其配套旗標。
3. 對於由資訊來源探索到的候選版本，使用 `vp run downstream:test`；失敗的嘗試會保留在 `scripts/release/downstream-compatibility.json` 中。檢視成功後，執行 `vp run downstream:bless --package @pantoken/name --version x.y.z` 以更新支援聲明。
4. 使用最低版本和新版本，執行實際的宿主、編譯器或建置工具檢查。若有需要，請重新對應目前的輸出格式；不要新增並行的舊格式輸出器。
5. 只有在檢查通過後才更新 `scripts/release/target-compatibility.json`，接著執行 `vp run sync:compatibility`、重新產生英文 API 文件，並新增 changeset。較新的版本會維持待處理狀態，直到已檢視的變更合併為止。當地語系化文件會另外處理。

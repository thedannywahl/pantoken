## 審查目標版本發布

每週目標版本工作流程會針對新的 WordPress 穩定版，以及具有明確 npm peer 的生態系統，建立審查 issue。對於其他目標，維護者每週檢查平台的官方發布說明，並手動建立審查 issue；沒有 issue 不代表支援新版本。若要擴大支援聲明：

1. 檢查該版本的輸出結構描述或整合變更，以及此表中的介接器。
2. 使用候選版本執行介接器的相容性命令，例如 `vp run @pantoken/postcss#check:compatibility -- 8.5.29`。預設命令會讀取此登錄中的每個 `testedVersions` 項目；成對環境可接受其對應旗標。
3. 對於由 feed 發現的候選版本，請使用 `vp run downstream:test`；失敗的嘗試會保留在 `scripts/release/downstream-compatibility.json`。成功完成審查後，執行 `vp run downstream:bless --package @pantoken/name --version x.y.z` 以更新支援聲明。
4. 在最低版本和新版本上執行真實宿主、編譯器或建置工具檢查。必要時重新對應目前的輸出格式；不要新增並行的舊格式輸出器。
5. 只有在檢查通過後才更新 `scripts/release/target-compatibility.json`，接著執行 `vp run sync:compatibility`、重新產生英文 API 文件，並新增 changeset。較新的版本會維持待審狀態，直到該變更完成合併。當地語系化文件會另行處理。

## ターゲットリリースのレビュー

週次のターゲットリリースワークフローでは、新しい安定版 WordPress リリースと、明示的な npm peer を持つエコシステムについて、レビュー用 issue を作成します。その他のターゲットについては、メンテナーが各プラットフォームの公式リリースノートを毎週確認し、手動でレビュー用 issue を作成します。issue がないことは、新しいリリースがサポートされていることを意味しません。保証対象を拡張するには、次の手順を実施します。

1. リリースの出力スキーマまたは統合の変更と、この表に記載されたアダプターを確認します。
2. 候補リリースを指定して、アダプターの互換性コマンドを実行します。例: `vp run @pantoken/postcss#check:compatibility -- 8.5.29`。既定のコマンドは、このレジストリのすべての `testedVersions` エントリーを読み込みます。ペア環境では、対応するフラグを指定できます。
3. フィードで検出された候補には `vp run downstream:test` を使用します。失敗した試行は `scripts/release/downstream-compatibility.json` に保存されます。レビューが成功したら、`vp run downstream:bless --package @pantoken/name --version x.y.z` を実行して保証対象を更新します。
4. 最小バージョンと新しいリリースで、実際のホスト、コンパイラー、またはビルドツールによるチェックを実施します。必要に応じて現在の出力形式を対応付けます。並行してレガシー形式のエミッターを追加しないでください。
5. チェックに合格した後にのみ `scripts/release/target-compatibility.json` を更新し、`vp run sync:compatibility` を実行して英語の API ドキュメントを再生成し、changeset を追加します。新しいリリースは、レビュー済みの変更が取り込まれるまで保留されます。ローカライズされたドキュメントは別途扱います。

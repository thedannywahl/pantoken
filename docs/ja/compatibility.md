# 互換性

このページでは、この pantoken ビルドが解決する Instructure UI のソースと、それらを使用するコンシューマーを記録します。対象バージョンは個別に扱います。検証済みのリリースのみを記載し、最後に検証したリリースより新しいリリースはレビューが必要です。`vp run sync:compatibility` で再生成してください。差分がある場合、`gate:compatibility` チェックは失敗します。

## 対象リリースのレビュー

週次の対象リリースワークフローでは、新しい安定版 WordPress リリースと、npm の peer を明示しているエコシステムについて、レビュー用 issue が作成されます。その他の対象については、メンテナーがプラットフォームの公式リリースノートを毎週確認し、手動でレビュー用 issue を作成します。issue がないからといって、新しいリリースがサポートされているわけではありません。サポート範囲を拡張するには、次の手順を実施します。

1. リリースの出力スキーマまたは統合の変更と、この表に記載されたアダプターを確認します。
2. 候補リリースを指定してアダプターの互換性コマンドを実行します。例: `vp run @pantoken/postcss#check:compatibility -- 8.5.29`。既定のコマンドは、このレジストリのすべての `testedVersions` エントリーを読み込みます。組み合わせ環境では、対応するフラグも指定できます。
3. フィードで検出された候補には、`vp run downstream:test` を使用します。失敗した試行は `scripts/release/downstream-compatibility.json` に保持されます。レビューが成功したら、`vp run downstream:bless --package @pantoken/name --version x.y.z` を実行してサポート範囲を更新します。
4. 最低バージョンと新しいリリースの両方で、実際のホスト、コンパイラー、またはビルドツールによるチェックを実施します。必要に応じて現在の出力形式を調整し、旧形式のエミッターを並行して追加しないでください。
5. チェックに合格してから `scripts/release/target-compatibility.json` を更新し、`vp run sync:compatibility` を実行して英語の API ドキュメントを再生成し、changeset を追加します。新しいリリースは、レビュー済みの変更が取り込まれるまで保留されます。ローカライズ済みドキュメントは別途対応します。

## 非推奨

# 互換性

このページでは、この pantoken ビルドが解決する Instructure UI のソースと、それらを使用するコンシューマーを記録します。ターゲットごとにバージョンは異なります。検証済みのリリースのみを対象とし、最後に検証したリリースより新しいリリースはレビューが必要です。`vp run sync:compatibility` で再生成してください。差分がある場合、`gate:compatibility` チェックは失敗します。

## ターゲットリリースのレビュー

週次のターゲットリリースワークフローでは、新しい安定版 WordPress リリースと、明示的な npm peer を持つエコシステムについてレビュー用 issue が作成されます。その他のターゲットについては、メンテナーが各プラットフォームの公式リリースノートを毎週確認し、手動でレビュー用 issue を作成します。issue がないことは、新しいリリースがサポートされていることを意味しません。サポート対象の主張を拡張するには、次の手順に従います。

1. リリースの出力スキーマまたは統合の変更と、この表に記載されたアダプターを確認します。
2. 候補リリースを指定してアダプターの互換性コマンドを実行します。例:
   `vp run @pantoken/postcss#check:compatibility -- 8.5.29`。既定のコマンドは、このレジストリにあるすべての
   `testedVersions` エントリーを読み込みます。ペアの環境では、対応する companion フラグを指定できます。
3. フィードで見つかった候補には `vp run downstream:test` を使用します。失敗した試行は
   `scripts/release/downstream-compatibility.json` に保持されます。レビューが成功したら、
   `vp run downstream:bless --package @pantoken/name --version x.y.z` を実行してサポート対象の主張を更新します。
4. 最小バージョンと新しいリリースの両方で、実際のホスト、コンパイラー、またはビルドツールによるチェックを行います。必要であれば現在の出力形式をマッピングし直してください。旧形式のエミッターを並行して追加しないでください。
5. チェックに合格した後でのみ `scripts/release/target-compatibility.json` を更新し、続けて
   `vp run sync:compatibility` を実行し、英語の API ドキュメントを再生成して changeset を追加します。新しいリリースは、レビュー済みの変更が取り込まれるまで保留のままです。ローカライズ済みドキュメントは別途管理されます。

## 非推奨

# Kompatibilitas

Halaman ini mencatat sumber Instructure UI yang digunakan build pantoken ini dan konsumen yang menggunakannya. Versi target dipisahkan: hanya rilis yang sudah diverifikasi yang dicantumkan, dan rilis yang lebih baru daripada rilis terakhir yang diverifikasi perlu ditinjau. Buat ulang dengan `vp run sync:compatibility`; pemeriksaan `gate:compatibility` akan gagal jika isinya menyimpang.

## Meninjau rilis target

Alur kerja rilis target mingguan membuka issue tinjauan untuk rilis WordPress stabil baru dan ekosistem dengan peer npm yang dinyatakan secara eksplisit. Untuk target lain, maintainer memeriksa catatan rilis resmi platform setiap minggu dan membuka issue tinjauan secara manual; tidak adanya issue bukan berarti rilis baru didukung. Untuk memperluas klaim:

1. Periksa skema output rilis atau perubahan integrasinya serta adapter pada tabel ini.
2. Jalankan perintah kompatibilitas adapter dengan rilis kandidat, misalnya
   `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. Perintah default membaca setiap entri `testedVersions` dari registri ini; lingkungan berpasangan menerima flag pendampingnya.
3. Untuk kandidat yang ditemukan melalui feed, gunakan `vp run downstream:test`; percobaan yang gagal tetap disimpan di
   `scripts/release/downstream-compatibility.json`. Setelah tinjauan berhasil, jalankan
   `vp run downstream:bless --package @pantoken/name --version x.y.z` untuk memperbarui klaim.
4. Jalankan pemeriksaan host, compiler, atau tool build yang sebenarnya pada rilis minimum dan rilis baru. Petakan ulang format output saat ini jika diperlukan; jangan menambahkan emitter format lama secara paralel.
5. Perbarui `scripts/release/target-compatibility.json` hanya setelah pemeriksaan berhasil, lalu jalankan
   `vp run sync:compatibility`, buat ulang dokumentasi API berbahasa Inggris, dan tambahkan changeset. Rilis yang lebih baru tetap tertunda hingga perubahan yang ditinjau tersebut digabungkan. Dokumentasi terlokalisasi ditangani secara terpisah.

## Penghentian penggunaan

Token upstream yang sudah dihapus tetapi masih disediakan pantoken sebagai shim kompatibilitas. Masing-masing tetap berfungsi hingga minor upstream `Removed in` diadopsi; setelah itu shim dihentikan dan rilis minor konsumen diterbitkan. Shim meneruskan ke token `Replacement` atau membekukan nilai terakhir yang diketahui.

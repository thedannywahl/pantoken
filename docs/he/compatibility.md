# תאימות

<!-- נוצר על ידי `vp run sync:compatibility`. אין לערוך ידנית; יש להריץ את הכותב ולבצע commit. -->

דף זה מתעד את מקורות Instructure UI שמהם גרסת pantoken זו פותרת את הנתונים, ואת הצרכנים שמשתמשים בהם. גרסאות היעד נפרדות: נטענות רק גרסאות שאומתו, וגרסאות חדשות מהגרסה האחרונה שאומתה דורשות בדיקה. יש ליצור מחדש באמצעות `vp run sync:compatibility`; הבדיקה `gate:compatibility` נכשלת אם יש סטייה.

## בדיקת גרסאות היעד

תהליך העבודה השבועי של גרסאות היעד פותח issue לבדיקה עבור גרסאות WordPress יציבות חדשות ועבור מערכות אקולוגיות עם peer מפורש של npm. עבור יעדים אחרים, המתחזקים בודקים מדי שבוע את הערות הגרסה הרשמיות של הפלטפורמה ופותחים issue לבדיקה באופן ידני; היעדר issue אינו מעיד על תמיכה בגרסה חדשה. כדי להרחיב טענה:

1. בדקו את סכמת הפלט של הגרסה או את שינויי האינטגרציה שלה ואת המתאם בטבלה זו.
2. הריצו את פקודת התאימות של המתאם עם גרסת המועמדת, למשל `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. פקודת ברירת המחדל קוראת כל ערך `testedVersions` מהרישום הזה; סביבות תואמות מקבלות את דגלי העזר שלהן.
3. עבור מועמדות שהתגלו באמצעות הפידים, השתמשו ב-`vp run downstream:test`; ניסיונות שנכשלו נשמרים ב-`scripts/release/downstream-compatibility.json`. לאחר בדיקה מוצלחת, הריצו את `vp run downstream:bless --package @pantoken/name --version x.y.z` כדי לעדכן את הטענה.
4. הריצו בדיקה מול מארח, מהדר או כלי בנייה אמיתי בגרסה המינימלית ובגרסה החדשה. התאימו מחדש את פורמט הפלט הנוכחי במידת הצורך; אל תוסיפו פולטי פורמט מקבילים מדור קודם.
5. עדכנו את `scripts/release/target-compatibility.json` רק לאחר שהבדיקות עוברות, ואז הריצו את `vp run sync:compatibility`, צרו מחדש את תיעוד ה-API באנגלית והוסיפו changeset. גרסאות חדשות יותר יישארו בהמתנה עד שהשינוי שנבדק ייכלל. התיעוד המקומי מטופל בנפרד.

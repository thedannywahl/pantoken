Esta página registra as fontes do Instructure UI das quais esta compilação do pantoken resolve dados e quais consumidores as utilizam. As versões-alvo são separadas: somente versões verificadas são declaradas, e versões posteriores à última versão verificada precisam de análise. ## Revisão de versões de destino

O workflow semanal de versões de destino abre uma issue de revisão para novos lançamentos estáveis do WordPress e ecossistemas com um peer explícito do npm. Para os outros alvos, os mantenedores verificam semanalmente as notas oficiais de lançamento da plataforma e abrem uma issue de revisão manualmente; a ausência de uma issue não significa que uma nova versão seja compatível. Para ampliar uma declaração:

1. Inspecione o esquema de saída da versão ou as alterações de integração e o adaptador desta tabela.
2. Execute o comando de compatibilidade do adaptador com a versão candidata, por exemplo, `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. O comando padrão lê todas as entradas `testedVersions` deste registro; ambientes pareados aceitam as respectivas flags complementares.
3. Para candidatos encontrados por feeds, use `vp run downstream:test`; as tentativas malsucedidas são mantidas em `scripts/release/downstream-compatibility.json`. Após uma revisão bem-sucedida, execute `vp run downstream:bless --package @pantoken/name --version x.y.z` para atualizar a declaração.
4. Execute uma verificação real do host, compilador ou ferramenta de compilação na versão mínima e na nova versão. Se necessário, mapeie novamente o formato de saída atual; não adicione emissores paralelos de formatos legados.
5. Atualize `scripts/release/target-compatibility.json` somente após a aprovação das verificações; em seguida, execute `vp run sync:compatibility`, gere novamente a documentação da API em inglês e adicione um changeset. As versões mais recentes permanecem pendentes até que a alteração revisada seja integrada. A documentação localizada é tratada separadamente.

## Descontinuações

Cada um continua funcionando até a adoção da versão minor upstream `Removed in`; nesse momento, a camada é removida e uma versão minor do consumidor é lançada. Uma camada de compatibilidade encaminha para um token `Replacement` ou congela seu último valor conhecido.

# Združljivost

<!-- Ustvarjeno z `vp run sync:compatibility`. Ne urejajte ročno; zaženite zapisovalnik in spremembe potrdite. -->

Ta stran beleži vire Instructure UI, iz katerih ta gradnja pantoken pridobiva podatke, in porabnike, ki jih uporabljajo. Ciljne različice so navedene ločeno: navajamo le preverjene izdaje, izdaje, novejše od zadnje preverjene izdaje, pa je treba pregledati. Stran znova ustvarite z `vp run sync:compatibility`; preverjanje `gate:compatibility` ne uspe, če se vsebina razlikuje.

## Pregled ciljnih izdaj

Tedenski potek dela za ciljne izdaje odpre zahtevek za pregled novih stabilnih izdaj WordPressa in ekosistemov z izrecnim npm peerom. Za druge cilje vzdrževalci tedensko preverjajo uradne opombe ob izdajah platforme in ročno odprejo zahtevek za pregled; odsotnost zahtevka ne pomeni, da je podprta nova izdaja. Če želite razširiti trditev:

1. Preglejte izhodno shemo izdaje oziroma spremembe integracije ter adapter v tej tabeli.
2. Zaženite ukaz za preverjanje združljivosti adapterja s kandidatno izdajo, na primer `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. Privzeti ukaz prebere vsak vnos `testedVersions` iz tega registra; seznanjena okolja sprejmejo spremljevalne zastavice.
3. Za kandidate, odkrite prek vira, uporabite `vp run downstream:test`; neuspešni poskusi se ohranijo v `scripts/release/downstream-compatibility.json`. Po uspešnem pregledu zaženite `vp run downstream:bless --package @pantoken/name --version x.y.z`, da posodobite trditev.
4. Izvedite preverjanje v pravem gostitelju, prevajalniku ali orodju za gradnjo pri najnižji in novi izdaji. Po potrebi prilagodite trenutno izhodno obliko; ne dodajajte vzporednih izdajalnikov zastarelih oblik.
5. Posodobite `scripts/release/target-compatibility.json` šele, ko preverjanja uspejo, nato zaženite `vp run sync:compatibility`, znova ustvarite angleško dokumentacijo API-ja in dodajte changeset. Novejše izdaje ostanejo v čakanju, dokler pregledana sprememba ni združena. Lokalizirana dokumentacija se ureja ločeno.

## Opustitve

Žetoni, ki jih je upstream odstranil, pantoken pa jih še vedno ponuja kot združljivostno plast. Vsak ostane delujoč do sprejetja svoje `Removed in` manjše upstream izdaje, nakar se združljivostna plast umakne in izda se manjša izdaja porabnika.

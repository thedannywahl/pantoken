## Revisión de versiones de destino

El flujo de trabajo semanal de versiones de destino abre una incidencia de revisión para las nuevas versiones estables de WordPress y los ecosistemas con una dependencia peer explícita de npm. Para los demás destinos, los responsables revisan semanalmente las notas oficiales de publicación de la plataforma y abren una incidencia de revisión manualmente; que no haya una incidencia no significa que una versión nueva sea compatible. Para ampliar una declaración de compatibilidad:

1. Inspecciona el esquema de salida o los cambios de integración de la versión y el adaptador de esta tabla.
2. Ejecuta el comando de compatibilidad del adaptador con la versión candidata, por ejemplo, `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. El comando predeterminado lee todas las entradas `testedVersions` de este registro; los entornos emparejados aceptan sus indicadores complementarios.
3. Para las versiones candidatas detectadas por el feed, usa `vp run downstream:test`; los intentos fallidos se conservan en `scripts/release/downstream-compatibility.json`. Después de una revisión satisfactoria, ejecuta `vp run downstream:bless --package @pantoken/name --version x.y.z` para actualizar la declaración de compatibilidad.
4. Ejecuta una comprobación real del entorno anfitrión, el compilador o la herramienta de compilación con la versión mínima y la nueva versión. Si es necesario, adapta el formato de salida actual; no agregues emisores paralelos de formatos heredados.
5. Actualiza `scripts/release/target-compatibility.json` solo después de que pasen las comprobaciones; luego ejecuta `vp run sync:compatibility`, regenera la documentación de la API en inglés y agrega un changeset. Las versiones posteriores siguen pendientes hasta que se incorpore el cambio revisado. La documentación localizada se gestiona por separado.

## Obsolescencias

Tokens que upstream dejó de incluir, pero que pantoken todavía distribuye como capa de compatibilidad. Cada uno seguirá funcionando hasta que se adopte la versión minor upstream de `Removed in`; entonces se retirará la capa de compatibilidad y se publicará una versión minor del consumidor. Una capa de compatibilidad reenvía a un token `Replacement` o conserva su último valor conocido.

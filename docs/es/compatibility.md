Esta página registra las fuentes de Instructure UI desde las que se resuelve esta compilación de pantoken y qué consumidores las usan. Las versiones de destino son independientes: solo se declaran versiones verificadas, y las versiones posteriores a la última verificada requieren una revisión. Regenera esta página con `vp run sync:compatibility`; la comprobación `gate:compatibility` falla si hay discrepancias.

## Revisión de versiones de destino

El flujo de trabajo semanal de versiones de destino abre una incidencia de revisión para las nuevas versiones estables de WordPress y los ecosistemas con una dependencia peer explícita de npm. Para los demás destinos, las personas responsables revisan semanalmente las notas oficiales de versión de la plataforma y abren manualmente una incidencia de revisión; que no haya una incidencia no significa que se admita una nueva versión. Para ampliar una declaración:

1. Inspecciona el esquema de salida de la versión o los cambios de integración, así como el adaptador de esta tabla.
2. Ejecuta el comando de compatibilidad del adaptador con la versión candidata, por ejemplo, `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. El comando predeterminado lee todas las entradas `testedVersions` de este registro; los entornos emparejados aceptan sus indicadores complementarios.
3. Para las candidatas descubiertas mediante feeds, usa `vp run downstream:test`; los intentos fallidos se conservan en `scripts/release/downstream-compatibility.json`. Después de una revisión satisfactoria, ejecuta `vp run downstream:bless --package @pantoken/name --version x.y.z` para actualizar la declaración.
4. Ejecuta una comprobación con el host, compilador o herramienta de compilación real en la versión mínima y en la nueva. Si hace falta, reasigna el formato de salida actual; no agregues emisores paralelos de formatos heredados.
5. Actualiza `scripts/release/target-compatibility.json` solo después de que pasen las comprobaciones; luego ejecuta `vp run sync:compatibility`, regenera la documentación de la API en inglés y agrega un changeset. Las versiones más recientes siguen pendientes hasta que se incorpore el cambio revisado. La documentación localizada se gestiona por separado.

## Obsolescencias

Tokens que upstream dejó de publicar y que pantoken aún distribuye como capa de compatibilidad. Cada uno sigue funcionando hasta que se adopte la versión minor de upstream `Removed in`; entonces se retira la capa y se publica una versión minor para los consumidores. Una capa de compatibilidad redirige a un token `Replacement` o fija su último valor conocido.

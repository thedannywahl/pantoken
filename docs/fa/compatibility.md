این صفحه منابع Instructure UI را ثبت می‌کند که این ساخت Pantoken از آن‌ها استفاده می‌کند و مشخص می‌کند کدام مصرف‌کنندگان از آن‌ها بهره می‌برند. نسخه‌های هدف جداگانه‌اند: فقط نسخه‌های تأییدشده اعلام می‌شوند و نسخه‌های جدیدتر از آخرین نسخهٔ تأییدشده نیازمند بررسی‌اند. برای بازتولید این صفحه، `vp run sync:compatibility` را اجرا کنید؛ بررسی `gate:compatibility` در صورت مغایرت شکست می‌خورد.

## بررسی نسخه‌های هدف

گردش‌کار هفتگی نسخه‌های هدف، برای نسخه‌های پایدار جدید WordPress و اکوسیستم‌هایی که وابستگی همتای صریح npm دارند، یک issue بررسی باز می‌کند. برای هدف‌های دیگر، نگه‌دارندگان هر هفته یادداشت‌های انتشار رسمی پلتفرم را بررسی می‌کنند و به‌صورت دستی issue بررسی باز می‌کنند؛ نبودن issue به این معنا نیست که نسخهٔ جدید پشتیبانی می‌شود. برای گسترش یک ادعا:

1. طرح‌وارهٔ خروجی یا تغییرات یکپارچه‌سازی نسخه و آداپتور این جدول را بررسی کنید.
2. فرمان سازگاری آداپتور را با نسخهٔ پیشنهادی اجرا کنید؛ برای نمونه، `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. فرمان پیش‌فرض همهٔ ورودی‌های `testedVersions` را از این رجیستری می‌خواند؛ محیط‌های جفت‌شده پرچم‌های همراه خود را می‌پذیرند.
3. برای نامزدهایی که از فید کشف شده‌اند، از `vp run downstream:test` استفاده کنید؛ تلاش‌های ناموفق در `scripts/release/downstream-compatibility.json` نگه‌داری می‌شوند. پس از بررسی موفق، `vp run downstream:bless --package @pantoken/name --version x.y.z` را اجرا کنید تا ادعا به‌روزرسانی شود.
4. بررسی واقعی میزبان، کامپایلر یا ابزار ساخت را روی حداقل نسخه و نسخهٔ جدید اجرا کنید. در صورت نیاز، قالب خروجی فعلی را بازنگاشت کنید؛ خروجی‌دهنده‌های موازیِ قالب قدیمی اضافه نکنید.
5. فقط پس از موفقیت بررسی‌ها، `scripts/release/target-compatibility.json` را به‌روزرسانی کنید؛ سپس `vp run sync:compatibility` را اجرا کنید، مستندات API انگلیسی را بازتولید کنید و یک changeset اضافه کنید. نسخه‌های جدیدتر تا زمان ادغام آن تغییرِ بازبینی‌شده همچنان در انتظار می‌مانند. مستندات بومی‌سازی‌شده جداگانه رسیدگی می‌شوند.

## منسوخ‌شده‌ها

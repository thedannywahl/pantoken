# التوافق

تسجّل هذه الصفحة مصادر Instructure UI التي يعتمد عليها إصدار pantoken هذا، والمستهلكين الذين يستخدمونها. الإصدارات المستهدفة منفصلة: لا نذكر إلا الإصدارات التي جرى التحقق منها، أما الإصدارات الأحدث من آخر إصدار جرى التحقق منه فتحتاج إلى مراجعة. أعد إنشاء الصفحة باستخدام `vp run sync:compatibility`؛ يفشل فحص `gate:compatibility` إذا لم تتطابق.

## مراجعة الإصدارات المستهدفة

تفتح آلية سير العمل الأسبوعية للإصدارات المستهدفة مشكلة مراجعة لإصدارات WordPress المستقرة الجديدة والأنظمة التي لديها تبعية نظير صريحة في npm. أما الأهداف الأخرى، فيراجع المشرفون ملاحظات الإصدار الرسمية للمنصة أسبوعيًا ويفتحون مشكلة مراجعة يدويًا؛ وعدم وجود مشكلة لا يعني أن الإصدار الجديد مدعوم. لتوسيع نطاق الادعاء:

1. افحص مخطط مخرجات الإصدار أو تغييرات التكامل والمحوّل الوارد في هذا الجدول.
2. شغّل أمر التوافق الخاص بالمحوّل مع الإصدار المرشح، مثلًا `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. يقرأ الأمر الافتراضي كل إدخال `testedVersions` من هذا السجل؛ وتقبل البيئات المقترنة أعلامها المصاحبة.
3. للمرشحين المكتشفين عبر الخلاصات، استخدم `vp run downstream:test`؛ وتُحتفظ بالمحاولات الفاشلة في `scripts/release/downstream-compatibility.json`. بعد نجاح المراجعة، شغّل `vp run downstream:bless --package @pantoken/name --version x.y.z` لتحديث الادعاء.
4. نفّذ فحصًا حقيقيًا للبيئة المضيفة أو المترجم أو أداة البناء عند الحد الأدنى للإصدار وعند الإصدار الجديد. أعد مواءمة تنسيق المخرجات الحالي إذا لزم الأمر؛ ولا تضف مُصدّرات تنسيق قديم موازية.
5. حدّث `scripts/release/target-compatibility.json` بعد اجتياز الفحوص فقط، ثم شغّل `vp run sync:compatibility`، وأعد إنشاء مستندات API الإنجليزية، وأضف مجموعة تغييرات. تظل الإصدارات الأحدث معلّقة إلى أن يُدمج التغيير الذي خضع للمراجعة. تُعالج الوثائق المترجمة كلٌّ على حدة.

## الإهمالات

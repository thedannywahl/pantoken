# التوافق

تسجّل هذه الصفحة مصادر Instructure UI التي يستند إليها هذا الإصدار من pantoken، والجهات المستهلكة لها. إصدارات الأهداف منفصلة: لا نذكر إلا الإصدارات التي جرى التحقق منها، وتتطلب الإصدارات الأحدث من آخر إصدار تم التحقق منه مراجعة. أعد إنشاء الصفحة باستخدام `vp run sync:compatibility`؛ إذ يفشل فحص `gate:compatibility` عند وجود اختلاف.

## مراجعة الإصدارات المستهدفة

تفتح سير عمل الإصدارات المستهدفة الأسبوعية مشكلة مراجعة لإصدارات WordPress المستقرة الجديدة والأنظمة التي تحدد تبعية peer صريحة على npm. أما الأهداف الأخرى، فيراجع المشرفون ملاحظات الإصدار الرسمية للمنصة أسبوعيًا ويفتحون مشكلة مراجعة يدويًا؛ وعدم وجود مشكلة لا يعني أن الإصدار الجديد مدعوم. لتوسيع ادعاء التوافق:

1. افحص مخطط مخرجات الإصدار أو تغييرات التكامل والمحوّل الوارد في هذا الجدول.
2. شغّل أمر التوافق الخاص بالمحوّل مع الإصدار المرشح، مثلًا `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. يقرأ الأمر الافتراضي كل إدخال `testedVersions` من هذا السجل؛ وتقبل البيئات المقترنة خياراتها المصاحبة.
3. للمرشحين المكتشفين عبر الخلاصات، استخدم `vp run downstream:test`؛ وتُحتفظ بالمحاولات الفاشلة في `scripts/release/downstream-compatibility.json`. بعد نجاح المراجعة، شغّل `vp run downstream:bless --package @pantoken/name --version x.y.z` لتحديث الادعاء.
4. نفّذ فحصًا حقيقيًا على البيئة المضيفة أو المترجم أو أداة البناء عند الإصدار الأدنى والإصدار الجديد. أعد مواءمة تنسيق المخرجات الحالي عند الضرورة؛ ولا تضف مُصدّرات موازية للتنسيقات القديمة.
5. حدّث `scripts/release/target-compatibility.json` بعد اجتياز الفحوصات فقط، ثم شغّل `vp run sync:compatibility`، وأعد إنشاء مستندات API الإنجليزية، وأضف changeset. تظل الإصدارات الأحدث قيد الانتظار إلى أن يُدمج التغيير الذي خضع للمراجعة. تُعالج الوثائق المترجمة بشكل منفصل.

## الإيقاف

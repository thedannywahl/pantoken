# Kompatibilitet

<!-- Genereret af `vp run sync:compatibility`. Rediger ikke manuelt; kør writer, og commit. -->

Denne side registrerer de Instructure UI-kilder, som dette pantoken-build løser fra, og hvilke forbrugere
der bruger dem. Målversioner er separate: Kun verificerede udgivelser angives, og udgivelser nyere end
den senest verificerede udgivelse skal gennemgås. Regenerér siden med `vp run sync:compatibility`; kontrollen
`gate:compatibility` fejler, hvis den afviger.

## Upstream-kilder

Design-tokens, Instructures tilpassede ikoner og Lucide-kataloget leverer data til det løste token-IR, som alle
pakker bruger. React-pakkerne `@instructure/ui-*` bruges kun af
`@pantoken/react-markdown`.

## Gennemgang af måludgivelser

Workflowet for ugentlige måludgivelser opretter en review-issue for nye stabile WordPress-udgivelser og
økosystemer med en eksplicit npm-peerafhængighed. For andre mål tjekker vedligeholderne platformens officielle
udgivelsesnoter ugentligt og opretter manuelt en review-issue; fravær af en issue betyder ikke, at en ny udgivelse
understøttes. Sådan udvider du en påstand:

1. Undersøg udgivelsens outputskema eller integrationsændringer og adapteren i denne tabel.
2. Kør adapterens kompatibilitetskommando med kandidatversionen, for eksempel
   `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. Standardkommandoen læser alle
   `testedVersions`-poster fra dette register; parrede miljøer accepterer deres ledsagende flag.
3. For kandidater fundet via feeds skal du bruge `vp run downstream:test`; mislykkede forsøg gemmes i
   `scripts/release/downstream-compatibility.json`. Efter en vellykket gennemgang skal du køre
   `vp run downstream:bless --package @pantoken/name --version x.y.z` for at opdatere påstanden.
4. Kør en kontrol med den faktiske vært, compiler eller build-værktøj ved minimumsversionen og den nye udgivelse. Tilpas det aktuelle
   outputformat om nødvendigt; tilføj ikke parallelle emittere til ældre formater.
5. Opdatér først `scripts/release/target-compatibility.json`, når kontrollen er bestået, og kør derefter
   `vp run sync:compatibility`, regenerér de engelske API-dokumenter, og tilføj en changeset. Nyere udgivelser
   forbliver afventende, indtil den gennemgåede ændring er landet. Lokaliseret dokumentation håndteres separat.

## Forældede tokens

Tokens, som upstream har fjernet, men som pantoken stadig leverer som kompatibilitets-shim. Hver shim virker, indtil
den tilhørende `Removed in` upstream-minorversion tages i brug; derefter udfases shim'en, og en forbrugerminorversion
udgives. En shim videresender enten til et `Replacement`-token eller fastfryser sin sidst kendte værdi.

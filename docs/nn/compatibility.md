# Kompatibilitet

<!-- Generert av `vp run sync:compatibility`. Endre ikkje for hand; køyr skribenten og commit. -->

Denne sida registrerer Instructure UI-kjeldene som denne pantoken-bygginga løyser frå, og kva for forbrukarar
som brukar dei. Målversjonar er separate: berre verifiserte utgivelsar blir kravde, og utgivelsar nyare enn
den siste verifiserte utgjevinga treng gjennomgang. Regenerer han med `vp run sync:compatibility`; sjekken
`gate:compatibility` feilar om han driv frå.

## Oppstrøms kjelder

Design-tokena, Instructure sine eigne ikon og Lucide-katalogen matar det løyste token-IR som alle
pakker brukar. Dei `@instructure/ui-*` React-pakkane blir berre brukte av
`@pantoken/react-markdown`.

## Gjennomgang av målutgjevingar

Den vekelege mål-utgjeving-arbeidsflyten opnar eit gjennomgangs-issue for nye stabile WordPress-utgjevingar og
økosystem med eksplisitt npm-peer. For andre mål sjekkar vedlikehaldarar plattformens offisielle
utgivingsnotat vekeleg og opnar eit gjennomgangs-issue manuelt; eit manglande issue betyr ikkje at ei ny utgjeving
er støtta. For å utvide eit krav:

1. Inspiser utgjevinga sitt produksjons-skjema eller integrasjonsendringar og adapteren i denne tabellen.
2. Kjør adapterens kompatibilitetskommando med kandidatutgjevinga, til dømes
   `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. Standardkommandoen les alle
   `testedVersions` oppføringar frå dette registeret; parade miljø tek imot sine følgjeflagg.
3. For feed-oppdaga kandidatar, bruk `vp run downstream:test`; feilslåtte forsøk blir halde på
   `scripts/release/downstream-compatibility.json`. Etter ein vellykka gjennomgang, køyr
   `vp run downstream:bless --package @pantoken/name --version x.y.z` for å oppdatere kravet.
4. Kjør ein reell host, compiler, eller build-tool-sjekk på minimums- og ny utgjeving. Remappa noverande
   utdataformat om nødvendig; ikkje legg til parallelle legacy-format-emittrar.
5. Oppdater `scripts/release/target-compatibility.json` først etter at sjekkane passerer, then køyr
   `vp run sync:compatibility`, regenerer engelske API-dokument og legg til eit changeset. Nyare utgjevingar
   vert ståande som pending til den gjennomgåtte endringa landar. Lokalisert dokumentasjon handterast separat.

til den `Removed in` oppstrøms-minoren er adoptert, då blir shim’en trekt og ein forbrukar-minor
skjer. Ein shim anten videresendrar til eit `Replacement` token eller fryser sist-kjende verdi.

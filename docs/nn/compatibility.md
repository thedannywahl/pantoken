# Kompatibilitet

<!-- Generert av `vp run sync:compatibility`. Ikkje rediger for hand; køyr skriptet som skriv fila og commit endringa. -->

Denne sida dokumenterer Instructure UI-kjeldene som dette pantoken-bygget løyser frå, og kva konsumentar som brukar dei. Målversjonar er separate: berre verifiserte utgåver er oppførte, og utgåver som er nyare enn den siste verifiserte utgåva, må vurderast. Generer sida på nytt med `vp run sync:compatibility`; kontrollen `gate:compatibility` feilar dersom innhaldet har endra seg.

## Vurdering av målutgåver

Arbeidsflyten for målutgåver kvar veke opprettar ei vurderingssak for nye stabile WordPress-utgåver og økosystem med ein eksplisitt npm-peer-avhengnad. For andre mål kontrollerer vedlikehaldarane dei offisielle utgåvenotata for plattforma kvar veke og opprettar ei vurderingssak manuelt; at ei sak manglar, tyder ikkje at ei ny utgåve er støtta. Slik utvidar du ein påstand:

1. Undersøk utdataformatet for utgåva eller integrasjonsendringane, og adapteren i denne tabellen.
2. Køyr adapterens kompatibilitetskommando med kandidatversjonen, til dømes `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. Standardkommandoen les alle oppføringane `testedVersions` frå dette registeret; parvisa miljø godtek flagga for den tilhøyrande varianten.
3. For kandidatar som blir oppdaga via datafeed, bruk `vp run downstream:test`; mislukka forsøk blir tekne vare på i `scripts/release/downstream-compatibility.json`. Etter ei vellukka vurdering køyrer du `vp run downstream:bless --package @pantoken/name --version x.y.z` for å oppdatere påstanden.
4. Køyr ein kontroll med den faktiske verten, kompilatoren eller byggverktøyet på minsteversjonen og den nye utgåva. Tilpass gjeldande utdataformat om nødvendig; ikkje legg til parallelle emitterar for eldre format.
5. Oppdater `scripts/release/target-compatibility.json` først etter at kontrollane er bestått, køyr deretter `vp run sync:compatibility`, generer dei engelske API-dokumenta på nytt og legg til ein changeset. Nyare utgåver står som ventande til den vurderte endringa er innlemma. Lokalisert dokumentasjon blir handtert separat.

## Avviklingar

Token som er fjerna oppstraums, men som pantoken framleis sender med som kompatibilitetslag. Kvart token held fram med å fungere fram til den oppstraums mindre utgåva `Removed in` blir teken i bruk. Då blir kompatibilitetslaget fjerna, og ei mindre utgåve av konsumenten blir publisert. Eit kompatibilitetslag anten vidaresender til eit `Replacement`-token eller frys den sist kjende verdien.

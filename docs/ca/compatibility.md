## Revisió de les versions de destinació

El flux de treball setmanal de versions de destinació obre una incidència de revisió per a les noves versions estables de WordPress i els ecosistemes amb una dependència npm explícita. Per a les altres destinacions, els responsables mantenen les notes de les versions oficials de la plataforma setmanalment i obren manualment una incidència de revisió; l’absència d’una incidència no vol dir que s’admeti una nova versió. Per ampliar una afirmació:

1. Inspeccioneu l’esquema de sortida o els canvis d’integració de la versió i l’adaptador d’aquesta taula.
2. Executeu l’ordre de compatibilitat de l’adaptador amb la versió candidata, per exemple, `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. L’ordre predeterminada llegeix totes les entrades `testedVersions` d’aquest registre; els entorns aparellats accepten els seus indicadors complementaris.
3. Per a les candidates detectades mitjançant fonts d’informació, feu servir `vp run downstream:test`; els intents fallits es conserven a `scripts/release/downstream-compatibility.json`. Després d’una revisió satisfactòria, executeu `vp run downstream:bless --package @pantoken/name --version x.y.z` per actualitzar l’afirmació.
4. Executeu una comprovació amb un entorn real d’amfitrió, compilador o eina de compilació, tant amb la versió mínima com amb la nova. Adapteu el format de sortida actual si cal; no afegiu emissors paral·lels de formats antics.
5. Actualitzeu `scripts/release/target-compatibility.json` només quan s’hagin superat les comprovacions; després, executeu `vp run sync:compatibility`, torneu a generar la documentació de l’API en anglès i afegiu un changeset. Les versions més noves continuen pendents fins que s’incorpora el canvi revisat. La documentació traduïda es gestiona per separat.

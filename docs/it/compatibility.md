Questa pagina registra le sorgenti Instructure UI da cui questa build di pantoken risolve e quali consumer
le utilizzano. Le versioni target sono separate: vengono dichiarate solo le release verificate e le release più recenti rispetto all'ultima verificata richiedono revisione. Rigenerarla con `vp run sync:compatibility`; il
controllo `gate:compatibility` fallisce se diverge.

## Revisione delle release target

Il flusso di lavoro settimanale per le release target apre un issue di revisione per nuove release stabili di WordPress e
per gli ecosistemi con un peer npm esplicito. Per altri target, i manutentori controllano settimanalmente le note di rilascio ufficiali della piattaforma e aprono manualmente un issue di revisione; l'assenza di un issue non significa che una nuova release sia supportata. Per estendere un claim:

1. Ispezionare lo schema di output della release o le modifiche di integrazione e l'adapter in questa tabella.
2. Eseguire il comando di compatibilità dell'adapter con la release candidata, per esempio
   `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. Il comando predefinito legge ogni
   voce `testedVersions` da questo registro; gli ambienti accoppiati accettano i loro flag companion.
3. Per i candidati scoperti dal feed, usare `vp run downstream:test`; i tentativi falliti vengono conservati in
   `scripts/release/downstream-compatibility.json`. Dopo una revisione riuscita, eseguire
   `vp run downstream:bless --package @pantoken/name --version x.y.z` per aggiornare il claim.
4. Eseguire un controllo reale su host, compilatore o build-tool al minimo e alla nuova release. Rimappare il formato di output corrente se necessario; non aggiungere emitter di formato legacy paralleli.
5. Aggiornare `scripts/release/target-compatibility.json` solo dopo il superamento dei controlli, quindi eseguire
   `vp run sync:compatibility`, rigenerare la documentazione API in inglese e aggiungere un changeset. Le release più recenti restano in sospeso fino a che la modifica revisionata non venga integrata. La documentazione localizzata è gestita separatamente.

## Deprecazioni

I token upstream rimossi che pantoken continua a fornire come shim di compatibilità. Ognuno è mantenuto funzionante fino a quando
il suo minor upstream `Removed in` non viene adottato, momento in cui lo shim viene ritirato e viene tagliato un minor consumer. Uno shim o inoltra a un token `Replacement` o congela il suo ultimo valore noto.

# Compatibilità

Questa pagina registra le origini di Instructure UI da cui questa build di pantoken risolve i dati e quali consumer le usano. Le versioni target sono separate: vengono dichiarate solo le release verificate e le release successive all'ultima verifica richiedono una revisione. Rigenerala con `vp run sync:compatibility`; il controllo `gate:compatibility` fallisce se il contenuto è cambiato.

## Revisione delle release target

Il workflow settimanale delle release target apre una issue di revisione per le nuove release stabili di WordPress e per gli ecosistemi con una dipendenza peer npm esplicita. Per gli altri target, i maintainer controllano settimanalmente le note di rilascio ufficiali della piattaforma e aprono manualmente una issue di revisione; l'assenza di una issue non significa che una nuova release sia supportata. Per estendere una dichiarazione:

1. Esamina lo schema di output della release o le modifiche all'integrazione e l'adattatore in questa tabella.
2. Esegui il comando di compatibilità dell'adattatore con la release candidata, ad esempio `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. Il comando predefinito legge ogni voce `testedVersions` di questo registro; gli ambienti abbinati accettano i rispettivi flag complementari.
3. Per le candidate rilevate dai feed, usa `vp run downstream:test`; i tentativi falliti vengono conservati in `scripts/release/downstream-compatibility.json`. Dopo una revisione riuscita, esegui `vp run downstream:bless --package @pantoken/name --version x.y.z` per aggiornare la dichiarazione.
4. Esegui un controllo con l'host, il compilatore o lo strumento di build effettivo alla versione minima e alla nuova release. Se necessario, rimappa il formato di output corrente; non aggiungere emitter paralleli per i formati legacy.
5. Aggiorna `scripts/release/target-compatibility.json` solo dopo il superamento dei controlli, quindi esegui `vp run sync:compatibility`, rigenera la documentazione API in inglese e aggiungi un changeset. Le release più recenti restano in attesa finché la modifica revisionata non viene integrata. La documentazione localizzata viene gestita separatamente.

## Deprecazioni

Token rimossi a monte che pantoken continua a distribuire come shim di compatibilità. Ognuno continua a funzionare fino all'adozione della minor upstream `Removed in`; a quel punto lo shim viene ritirato e viene rilasciata una minor del consumer. Uno shim inoltra a un token `Replacement` oppure mantiene invariato il suo ultimo valore noto.

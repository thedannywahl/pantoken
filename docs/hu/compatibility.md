# Kompatibilitás

<!-- A `vp run sync:compatibility` által generálva. Ne szerkeszd kézzel; futtasd az írót, majd commitold. -->

Ez az oldal rögzíti, hogy ez a pantoken-build mely Instructure UI-forrásokból old fel adatokat, és mely fogyasztók használják ezeket. A célverziók különállóak: csak az ellenőrzött kiadásokra vonatkozó állításokat teszünk, az utolsó ellenőrzött kiadásnál újabb kiadások pedig felülvizsgálatot igényelnek. A `vp run sync:compatibility` paranccsal generálhatod újra; a `gate:compatibility` ellenőrzés hibát jelez, ha eltérést talál.

## Célkiadások felülvizsgálata

A heti célkiadás-munkafolyamat felülvizsgálati issue-t nyit az új stabil WordPress-kiadásokhoz, valamint azokhoz az ökoszisztémákhoz, amelyeknek explicit npm peer-függőségük van. Más célplatformok esetén a karbantartók hetente ellenőrzik a platform hivatalos kiadási megjegyzéseit, és kézzel nyitnak felülvizsgálati issue-t; egy hiányzó issue nem jelenti azt, hogy az új kiadás támogatott. Egy állítás kiterjesztéséhez:

1. Vizsgáld meg a kiadás kimeneti sémáját vagy integrációs módosításait, valamint a táblázatban szereplő adaptert.
2. Futtasd az adapter kompatibilitási parancsát a jelölt kiadással, például a `vp run @pantoken/postcss#check:compatibility -- 8.5.29` parancsot. Az alapértelmezett parancs a regiszter minden `testedVersions` bejegyzését beolvassa; a párosított környezetek elfogadják a kiegészítő kapcsolóikat.
3. A hírfolyamból felderített jelöltekhez használd a `vp run downstream:test` parancsot; a sikertelen próbálkozások megmaradnak a `scripts/release/downstream-compatibility.json` helyen. Sikeres felülvizsgálat után futtasd a `vp run downstream:bless --package @pantoken/name --version x.y.z` parancsot az állítás frissítéséhez.
4. Futtass valós gazdakörnyezet-, fordító- vagy buildeszköz-ellenőrzést a minimális és az új kiadáson. Szükség esetén képezd le újra a jelenlegi kimeneti formátumot; ne adj hozzá párhuzamos, örökölt formátumokat kibocsátó emitereket.
5. Csak az ellenőrzések sikeres lefutása után frissítsd a `scripts/release/target-compatibility.json` fájlt, majd futtasd a `vp run sync:compatibility` parancsot, generáld újra az angol API-dokumentációt, és adj hozzá changesetet. Az újabb kiadások felülvizsgálat alatt maradnak, amíg az ellenőrzött módosítás be nem kerül. A lokalizált dokumentációt külön kell kezelni.

## Kivezetések

Az upstream által eltávolított, de a pantoken által kompatibilitási shimként továbbra is szállított tokenek. Mindegyik működőképes marad, amíg az upstream `Removed in` minor kiadása be nem kerül; ekkor a shim megszűnik, és új minor fogyasztói kiadás készül. A shim vagy egy `Replacement` tokenre irányít át, vagy rögzíti az utoljára ismert értékét.

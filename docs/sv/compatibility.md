# Kompatibilitet

<!-- Genererad av `vp run sync:compatibility`. Redigera inte för hand; kör skrivaren och checka in. -->

Den här sidan dokumenterar Instructure UI-källorna som pantoken-bygget hämtar data från och vilka konsumenter som använder dem. Målversionerna är separata: endast verifierade versioner anges, och versioner som är nyare än den senast verifierade behöver granskas. Generera om sidan med `vp run sync:compatibility`; kontrollen `gate:compatibility` misslyckas om den inte är synkroniserad.

## Granskning av målversioner

Arbetsflödet för målversioner varje vecka skapar ett granskningsärende för nya stabila WordPress-versioner och ekosystem med en uttrycklig npm-peer. För andra mål kontrollerar underhållarna plattformens officiella versionsinformation varje vecka och skapar ett granskningsärende manuellt; att ett ärende saknas betyder inte att en ny version stöds. Så här utökar du ett anspråk:

1. Granska utdataformatet eller integrationsändringarna i versionen och adaptern i den här tabellen.
2. Kör adapterns kompatibilitetskommando med den föreslagna versionen, till exempel
   `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. Standardkommandot läser varje
   `testedVersions`-post från det här registret; parade miljöer godtar motsvarande flaggor.
3. För kandidater som hittats via flödet använder du `vp run downstream:test`; misslyckade försök sparas i
   `scripts/release/downstream-compatibility.json`. Kör `vp run downstream:bless --package @pantoken/name --version x.y.z` efter en godkänd granskning
   för att uppdatera anspråket.
4. Kör en kontroll med den riktiga värden, kompilatorn eller byggverktyget för både den lägsta och den nya versionen. Mappa om det aktuella utdataformatet vid behov; lägg inte till parallella utmatningar av äldre format.
5. Uppdatera `scripts/release/target-compatibility.json` först när kontrollerna har godkänts. Kör sedan
   `vp run sync:compatibility`, generera om den engelska API-dokumentationen och lägg till en changeset. Nyare versioner förblir under granskning tills ändringen har tagits in. Lokaliserad dokumentation hanteras separat.

## Föråldringar

Token som tagits bort uppströms men som pantoken fortfarande levererar som kompatibilitetslösningar. Varje sådan lösning fortsätter att fungera tills dess `Removed in` uppströmsversion börjar användas. Då tas lösningen bort och en ny minorversion av konsumenten släpps. En lösning vidarebefordrar antingen till en `Replacement`-token eller låser det senast kända värdet.

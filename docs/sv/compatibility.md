# Kompatibilitet

<!-- Genererad av `vp run sync:compatibility`. Redigera inte för hand; kör skrivaren och checka in resultatet. -->

Den här sidan dokumenterar Instructure UI-källorna som det här pantoken-bygget hämtar data från, och vilka konsumenter som använder dem. Målversionerna är separata: endast verifierade versioner anges, och versioner som är nyare än den senast verifierade behöver granskas. Generera om sidan med `vp run sync:compatibility`; kontrollen `gate:compatibility` misslyckas om innehållet avviker.

## Uppströmskällor

Designtokenen, Instructures anpassade ikoner och Lucide-katalogen matar den lösta token-IR som alla paket använder. React-paketen `@instructure/ui-*` används endast av `@pantoken/react-markdown`.

## Granskning av målplattformsversioner

Det veckovisa arbetsflödet för målplattformsversioner öppnar ett granskningsärende för nya stabila WordPress-versioner och ekosystem med en uttrycklig npm-peer. För andra målplattformar kontrollerar underhållarna plattformens officiella versionsinformation varje vecka och öppnar granskningsärenden manuellt; att ett ärende saknas betyder inte att en ny version stöds. Så här utökar du ett anspråk:

1. Granska versionens utdataschema eller integrationsändringar och adaptern i den här tabellen.
2. Kör adapterns kompatibilitetskommando med den föreslagna versionen, till exempel
   `vp run @pantoken/postcss#check:compatibility -- 8.5.29`. Standardkommandot läser varje
   `testedVersions`-post från det här registret; miljöer med parade versioner accepterar tillhörande flaggor.
3. För kandidater som hittats via flöden använder du `vp run downstream:test`; misslyckade försök sparas i
   `scripts/release/downstream-compatibility.json`. Efter en godkänd granskning kör du
   `vp run downstream:bless --package @pantoken/name --version x.y.z` för att uppdatera anspråket.
4. Kör en kontroll med den verkliga värdplattformen, kompilatorn eller byggverktyget för den lägsta och den nya versionen. Mappa om det aktuella utdataformatet vid behov; lägg inte till parallella emitterare för äldre format.
5. Uppdatera `scripts/release/target-compatibility.json` först när kontrollerna har godkänts, kör sedan
   `vp run sync:compatibility`, generera om den engelska API-dokumentationen och lägg till en changeset. Nyare versioner förblir väntande tills den granskade ändringen har landats. Lokaliserad dokumentation hanteras separat.

## Utfasningar

Token som tagits bort uppströms men som pantoken fortfarande levererar som kompatibilitetslösningar. Varje sådan lösning fortsätter fungera tills dess `Removed in`-uppströmsminorversion införs; då tas lösningen bort och en minorversion av konsumentpaketet släpps. En lösning vidarebefordrar antingen till en `Replacement`-token eller låser dess senast kända värde.

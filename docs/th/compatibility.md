หน้านี้บันทึกแหล่งที่มาของ Instructure UI ที่บิลด์ pantoken นี้ใช้แก้ไข และระบุว่าผู้ใช้รายใดใช้แหล่งเหล่านั้นบ้าง เวอร์ชันเป้าหมายแยกจากกัน โดยระบุเฉพาะรีลีสที่ตรวจสอบแล้ว ส่วนรีลีสที่ใหม่กว่ารีลีสล่าสุดที่ตรวจสอบแล้วต้องได้รับการทบทวน สร้างหน้านี้ใหม่ด้วย `vp run sync:compatibility`; การตรวจสอบ `gate:compatibility` จะไม่ผ่านหากข้อมูลคลาดเคลื่อน

## การทบทวนรีลีสเป้าหมาย

เวิร์กโฟลว์รีลีสเป้าหมายรายสัปดาห์จะเปิด issue เพื่อทบทวนรีลีส WordPress เสถียรใหม่และระบบนิเวศที่ระบุ npm peer ไว้อย่างชัดเจน สำหรับเป้าหมายอื่น ผู้ดูแลจะตรวจสอบบันทึกรีลีสอย่างเป็นทางการของแพลตฟอร์มทุกสัปดาห์ และเปิด issue เพื่อทบทวนด้วยตนเอง การไม่มี issue ไม่ได้หมายความว่ารองรับรีลีสใหม่แล้ว หากต้องการขยายการรับรอง:

1. ตรวจสอบสคีมาเอาต์พุตหรือการเปลี่ยนแปลงการผสานรวมของรีลีส และ adapter ในตารางนี้
2. เรียกใช้คำสั่งตรวจสอบความเข้ากันได้ของ adapter โดยระบุรีลีสที่ต้องการ เช่น `vp run @pantoken/postcss#check:compatibility -- 8.5.29` คำสั่งเริ่มต้นจะอ่านทุกรายการ `testedVersions` จากรีจิสทรีนี้ ส่วนสภาพแวดล้อมที่จับคู่กันให้ใช้แฟล็กของคู่ที่เกี่ยวข้อง
3. สำหรับตัวเลือกที่ค้นพบจากฟีด ให้ใช้ `vp run downstream:test`; ความพยายามที่ไม่สำเร็จจะถูกเก็บไว้ใน `scripts/release/downstream-compatibility.json` หลังจากทบทวนสำเร็จแล้ว ให้เรียกใช้ `vp run downstream:bless --package @pantoken/name --version x.y.z` เพื่ออัปเดตการรับรอง
4. ตรวจสอบโฮสต์ คอมไพเลอร์ หรือเครื่องมือบิลด์จริงกับรีลีสขั้นต่ำและรีลีสใหม่ หากจำเป็น ให้ปรับรูปแบบเอาต์พุตปัจจุบันใหม่ ห้ามเพิ่มตัวสร้างเอาต์พุตรูปแบบเก่าแบบคู่ขนาน
5. อัปเดต `scripts/release/target-compatibility.json` หลังจากผ่านการตรวจสอบแล้วเท่านั้น จากนั้นเรียกใช้ `vp run sync:compatibility` สร้างเอกสาร API ภาษาอังกฤษใหม่ และเพิ่ม changeset รีลีสที่ใหม่กว่าจะยังคงรอการตรวจสอบจนกว่าการเปลี่ยนแปลงที่ผ่านการทบทวนจะถูกรวม เอกสารภาษาท้องถิ่นจัดการแยกต่างหาก

หน้านี้บันทึกแหล่งที่มาของ Instructure UI ที่บิลด์นี้ของ pantoken ใช้แก้ไข และระบุว่าใครเป็นผู้ใช้ แพลตฟอร์มเป้าหมายมีเวอร์ชันแยกจากกัน โดยระบุเฉพาะรีลีสที่ตรวจสอบแล้ว และรีลีสที่ใหม่กว่ารีลีสล่าสุดที่ตรวจสอบแล้วต้องได้รับการทบทวน สร้างหน้านี้ใหม่ด้วย `vp run sync:compatibility`; การตรวจสอบ `gate:compatibility` จะไม่ผ่านหากข้อมูลคลาดเคลื่อน

## การทบทวนรีลีสเป้าหมาย

เวิร์กโฟลว์รีลีสเป้าหมายรายสัปดาห์จะเปิด issue สำหรับทบทวนรีลีส WordPress รุ่นเสถียรใหม่และระบบนิเวศที่ระบุ npm peer ไว้อย่างชัดเจน สำหรับเป้าหมายอื่น ผู้ดูแลจะตรวจสอบบันทึกรีลีสอย่างเป็นทางการของแพลตฟอร์มทุกสัปดาห์และเปิด issue เพื่อทบทวนด้วยตนเอง การไม่มี issue ไม่ได้หมายความว่ารองรับรีลีสใหม่ หากต้องการขยายการรับรอง:

1. ตรวจสอบสคีมาของเอาต์พุตรีลีสหรือการเปลี่ยนแปลงการผสานรวม รวมถึง adapter ในตารางนี้
2. เรียกใช้คำสั่งตรวจสอบความเข้ากันได้ของ adapter กับรีลีสที่กำลังพิจารณา เช่น
   `vp run @pantoken/postcss#check:compatibility -- 8.5.29` คำสั่งเริ่มต้นจะอ่านรายการ `testedVersions` ทุกรายการจากรีจิสทรีนี้ สภาพแวดล้อมแบบจับคู่รองรับแฟล็กของคู่ที่เกี่ยวข้อง
3. สำหรับรีลีสที่ค้นพบจากฟีด ให้ใช้ `vp run downstream:test`; ระบบจะเก็บความพยายามที่ไม่สำเร็จไว้ใน `scripts/release/downstream-compatibility.json` หลังทบทวนสำเร็จแล้ว ให้เรียกใช้ `vp run downstream:bless --package @pantoken/name --version x.y.z` เพื่ออัปเดตการรับรอง
4. ตรวจสอบกับโฮสต์ คอมไพเลอร์ หรือเครื่องมือบิลด์จริง ทั้งรีลีสขั้นต่ำและรีลีสใหม่ หากจำเป็นให้ปรับรูปแบบเอาต์พุตปัจจุบัน อย่าเพิ่มตัวปล่อยรูปแบบเดิมแบบขนาน
5. อัปเดต `scripts/release/target-compatibility.json` หลังจากการตรวจสอบผ่านแล้วเท่านั้น จากนั้นเรียกใช้ `vp run sync:compatibility` สร้างเอกสาร API ภาษาอังกฤษใหม่ และเพิ่ม changeset รีลีสที่ใหม่กว่าจะยังอยู่ระหว่างรอจนกว่าการเปลี่ยนแปลงที่ผ่านการทบทวนจะถูกรวม เอกสารภาษาท้องถิ่นจัดการแยกต่างหาก

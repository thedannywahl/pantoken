यह पृष्ठ उन Instructure UI स्रोतों का रिकॉर्ड रखता है जिनसे यह pantoken बिल्ड समाधान करता है, और यह भी कि कौन-से उपभोक्ता उनका उपयोग करते हैं। लक्ष्य संस्करण अलग-अलग हैं: केवल सत्यापित रिलीज़ का दावा किया गया है, और पिछली सत्यापित रिलीज़ से नए रिलीज़ की समीक्षा आवश्यक है। इसे `vp run sync:compatibility` से फिर से जनरेट करें; यदि इसमें कोई अंतर आता है, तो `gate:compatibility` जाँच विफल हो जाती है।

## लक्ष्य रिलीज़ की समीक्षा

साप्ताहिक लक्ष्य-रिलीज़ वर्कफ़्लो, नए स्थिर WordPress रिलीज़ और स्पष्ट npm peer वाले इकोसिस्टम के लिए समीक्षा इश्यू खोलता है। अन्य लक्ष्यों के लिए, अनुरक्षक प्लेटफ़ॉर्म के आधिकारिक रिलीज़ नोट्स साप्ताहिक रूप से जाँचते हैं और मैन्युअल रूप से समीक्षा इश्यू खोलते हैं; इश्यू न होना यह नहीं दर्शाता कि कोई नई रिलीज़ समर्थित है। किसी दावे का विस्तार करने के लिए:

1. रिलीज़ की आउटपुट स्कीमा या इंटीग्रेशन में हुए बदलावों और इस तालिका के एडेप्टर की जाँच करें।
2. उम्मीदवार रिलीज़ के साथ एडेप्टर का संगतता कमांड चलाएँ, उदाहरण के लिए
   `vp run @pantoken/postcss#check:compatibility -- 8.5.29`। डिफ़ॉल्ट कमांड इस रजिस्ट्री की हर
   `testedVersions` प्रविष्टि पढ़ता है; युग्मित परिवेशों में उनके सहायक फ़्लैग स्वीकार किए जाते हैं।
3. फ़ीड से खोजे गए उम्मीदवारों के लिए `vp run downstream:test` का उपयोग करें; विफल प्रयास
   `scripts/release/downstream-compatibility.json` में रखे जाते हैं। सफल समीक्षा के बाद, दावे को अपडेट करने के लिए
   `vp run downstream:bless --package @pantoken/name --version x.y.z` चलाएँ।
4. न्यूनतम और नए रिलीज़ पर वास्तविक होस्ट, कंपाइलर या बिल्ड-टूल जाँच चलाएँ। ज़रूरत पड़ने पर वर्तमान आउटपुट फ़ॉर्मैट को मैप करें; पुराने फ़ॉर्मैट के समानांतर एमिटर न जोड़ें।
5. जाँचें सफल होने के बाद ही `scripts/release/target-compatibility.json` अपडेट करें, फिर
   `vp run sync:compatibility` चलाएँ, अंग्रेज़ी API दस्तावेज़ फिर से जनरेट करें और changeset जोड़ें। समीक्षा किया गया बदलाव शामिल होने तक नए रिलीज़ लंबित रहेंगे। स्थानीयकृत दस्तावेज़ों को अलग से संभाला जाता है।

## डेप्रिकेशन

वे टोकन जिन्हें अपस्ट्रीम ने हटा दिया है, लेकिन pantoken अब भी संगतता शिम के रूप में उपलब्ध कराता है। प्रत्येक टोकन तब तक काम करता रहेगा, जब तक उसका `Removed in` अपस्ट्रीम माइनर संस्करण अपनाया नहीं जाता; उसके बाद शिम हटा दिया जाता है और उपभोक्ता के लिए माइनर रिलीज़ जारी की जाती है। शिम या तो किसी `Replacement` टोकन को फ़ॉरवर्ड करता है या उसका पिछला ज्ञात मान स्थिर रखता है।

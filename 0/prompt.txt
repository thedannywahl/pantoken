## 2. How themes / `@custom-media` are resolved

- **Theme switch is runtime, attribute-based:** `/Users/dwahl/Scripts/pantoken/docs/.vitepress/theme/theme.ts` `applyTheme()` sets `&lt;html data-pantoken-theme="canvas"&gt;` and persists it. UI is `/Users/dwahl/Scripts/pantoken/docs/.vitepress/theme/components/ThemeSelector.vue`; bootstrap in `/Users/dwahl/Scripts/pantoken/docs/.vitepress/theme/index.ts` (line 42).
- **Token *values* re-theme** via `site-themes.css` (`:root[data-pantoken-theme="…"]`), imported in `theme/index.ts` line 9.
- **The `@media (--theme-*)` rules are lowered away at build time.** The shipped `@pantoken/components/components.css` is a single-theme (rebrand) sheet; the `themeCustomMedia` plugin prunes the canvas branches. This is documented verbatim in `/Users/dwahl/Scripts/pantoken/docs/scripts/lib/scope-components.ts` lines 6–19, which even names the billboard case:

&gt; *"A theme rule that changes which TOKEN a property references (e.g. billboard's `-clickable:hover` border-color: `--instui-color-text-base` → `--instui-component-link-text-color`) can't be recovered by re-scoping token VALUES alone, so those overrides never appear when the reader switches themes."*

- **The recovery mechanism** (`scopedComponentsCss` in `scope-components.ts`) diffs `componentsCss({theme:"rebrand"})` against `componentsCss({theme:"canvas"})`, then re-emits the canvas/canvasHighContrast-only rules **scoped under `:root[data-pantoken-theme="…"]`**. It writes this multi-theme sheet to `docs/public/demos-assets/components.css` (see `/Users/dwahl/Scripts/pantoken/docs/scripts/demos.ts` line 52).

I confirmed the scoped override **does exist** in the staged artifact `/Users/dwahl/Scripts/pantoken/docs/public/demos-assets/components.css` (lines 5944–5973):

```css
/* canvas theme overrides — attribute-scoped for the docs runtime theme switch */
:root[data-pantoken-theme="canvas"] .instui-billboard.-clickable:hover {
    border-color: var(--instui-component-link-text-color);
  }
```

## 3. Where the source CSS comes from (and the root cause)

Two different sheets, and this is the bug:

- **The markdown generator** (`build-css-api.ts` line 132) reads from `/Users/dwahl/Scripts/pantoken/formats/components/generated/*.css` — a **built artifact** (not `dist`, chosen because it retains doc comments). I confirmed `formats/components/generated/billboard.css` and `generated/components.css` are **rebrand-only**: no `@media (--theme-canvas)`, no scoped overrides. So the documented tokens/rules never carry the canvas hover value.
- **The inline live preview** renders in the main document, which loads its component CSS from `/Users/dwahl/Scripts/pantoken/docs/.vitepress/theme/index.ts` **line 12: `import "@pantoken/components/components.css"`** — the **single-theme rebrand sheet with the theme `@media` branches pruned**.

The `demoMarkdownIt` `cssUrls` list in `config.ts` (lines 413–426), which *does* include `demos-assets/components.css` with the scoped canvas overrides, is **only used for iframe demos** (`resolveDemo` → runner `?css=`). The inline CSS-API `@example` preview (`live.wrap`, `index.ts` line 213) is plain in-page HTML and never receives those `cssUrls`.

**Root cause:** When the reader selects "canvas", `data-pantoken-theme="canvas"` re-themes token *values*, but the billboard `-clickable:hover` rule loaded in the main document still points at `--instui-color-text-base` (from the pruned rebrand sheet). The rule that would repoint it to `--instui-component-link-text-color` (link) exists only in `demos-assets/components.css`, which the main document does not import. Result: the hover border "falls back to text" instead of resolving to link. This is precisely the failure `scope-components.ts` was written to prevent — the fix was applied to the `/play` iframe sheet but not to the main-document inline previews.

## 3. Interactive vs. non-interactive mode, flag parsing

Yes, there's a narrow interactive mode, defined in `packages/scaffold/src/cli.ts`:

```ts
export function shouldPromptForDir(dirFlag: string | undefined, isTTY: boolean | undefined): boolean {
  return dirFlag === undefined &amp;&amp; isTTY === true;
}
```

- If `--dir` is **omitted** and `process.stdin.isTTY === true` → prompts once via readline: `"Project directory (. for current folder): "` (blank answer → `"."`).
- Otherwise (non-TTY, e.g. CI/piped, or `--dir` given) → uses `parsed.dirFlag ?? "."` silently, no prompt.

Flags supported (all hand-parsed in `parseArgs`):
- Positional platform arg (first non-`-` token)
- `--dir &lt;path&gt;`
- `--help` / `-h`
- Anything else throws `Unknown option "&lt;arg&gt;"`.

There is **no** `--yes`/`--silent`/`--non-interactive` flag — non-interactive behavior is implicit from `!isTTY` or presence of `--dir`. This exact contract is locked in by tests in `packages/scaffold/tests/cli.test.ts` (prompt-on-TTY, no-prompt-with-`--dir`, blank-answer-fallback, non-TTY-defaults-to-`.`, unknown-option/platform rejections, etc.) — any refactor introducing a CLI framework needs to preserve these behaviors or update these tests.

The `pantoken-ai` CLI (`ai/pantoken-ai/bin/pantoken-ai.mjs`) layers `init`/`scaffold` subcommands and a `--tool &lt;name&gt;` flag on top, via its own separate `flag()`/`requireChoice()` helpers — it does not reuse `packages/scaffold/src/cli.ts`'s parser, it reuses only `scaffoldAndInit`/`installAgentAssets` from `@pantoken/ai`'s index.

- **Each platform package** exports a Bingo Preset via a `./scaffold-preset` subpath export:
  - `formats/components/src/scaffold-preset.ts` → `presetComponents`
  - `renderers/react/src/scaffold-preset.ts` → `presetReact`
  - `renderers/vue/src/scaffold-preset.ts` → `presetVue`
  - `renderers/web-components/src/scaffold-preset.ts` → `presetWebComponents`
  - `renderers/angular/src/scaffold-preset.ts` → `presetAngular`

  2. Calls `bingo-stratum`'s `producePreset(preset, { offline: true, options: { name: projectName } })`, wrapped in try/catch.

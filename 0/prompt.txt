## Token model and InstUI resolution in `pantoken`

### 1. The canonical token IR — `@pantoken/model`

The IR is defined as pure TypeScript type contracts (zero runtime, zero deps) in `/Users/dwahl/Scripts/pantoken/packages/model/src/index.ts`. The canonical unit is the `Token` interface, aligned to the CSS `@property` schema:

```ts
export interface Token {
  name: string;      // custom-property name, e.g. --instui-color-background-base
  syntax: string;    // @property syntax: "&lt;color&gt;", "&lt;length&gt;", "&lt;image&gt;", or "*" for contextual
  inherits: boolean; // @property inherits flag
  value: string;     // a concrete value, a var(...) reference, or a light-dark(a, b) pair
  themed?: boolean;  // true when light/dark resolutions differ (value is a light-dark())
  refersTo?: string; // the token this one references, when value is a single var(...)
  meta?: TokenMeta;  // non-value metadata (icons, deprecation, color modifiers)
}
```

Value representation (confirmed against generated output in `/Users/dwahl/Scripts/pantoken/formats/tokens/generated/canvas.json` and `rebrand.json`):

- **Primitives** carry literal values — hex colors and rem/px lengths. These are the resolution endpoints:
  - `--instui-primitive-color-white` → `"#ffffff"` (syntax `&lt;color&gt;`)
  - `--instui-primitive-size-size12` → `"0.75rem"` (syntax `*`)
- **Semantic / layout / component tokens** carry `var(...)` references, never inlined literals, plus a `refersTo` back-pointer:
  - `--instui-spacing-space-md` → `"var(--instui-primitive-size-size12)"`, `refersTo: "--instui-primitive-size-size12"`
- **Themed colors** use `light-dark()` wrapping both resolved references, with `themed: true`:
  - `--instui-color-background-base` → `"light-dark(var(--instui-primitive-color-white), var(--instui-primitive-color-grey-grey200))"`, `themed: true`

Key point for 1:1 matching: the IR stores each token's **authored** value (a reference or literal), not a fully-flattened leaf. To compare against a component's computed CSS you must walk the `refersTo` chain down to a primitive literal yourself (see #5).

### 4. How component CSS references tokens — `var()`, not resolved literals

Component records author CSS with **`var(--instui-...)` references**, and the emitted CSS keeps them as `var()` — nothing is flattened to literals. Example: `/Users/dwahl/Scripts/pantoken/formats/components/src/components/button.ts`:

```css
min-height: var(--instui-component-base-button-medium-height);
background: var(--instui-color-background-interactive-action-primary-base);
color: var(--instui-color-text-interactive-action-primary-base);
```

The `css` tag (`/Users/dwahl/Scripts/pantoken/formats/components/src/lib/css.ts`) is an identity template — it emits byte-for-byte what was authored. Confirmed in generated output: `/Users/dwahl/Scripts/pantoken/formats/components/generated/button.css` contains 88 `var(--instui-...)` occurrences; every component `.css` keeps references. Definition/record plumbing is in `/Users/dwahl/Scripts/pantoken/formats/components/src/lib/define.ts`.

Consequence: to compare a rendered pantoken component's computed CSS against "the actual token IR value," the browser resolves the `var()` cascade at runtime; to compare against the IR statically you must resolve the same reference chain (#5) and match the final literal.

### 5. Resolving a token reference to its final literal value

There is no single "flatten to literal" resolver exported — resolution is split:

- **Authoring/ingestion resolver** (Tokens Studio `{path}` → `var(...)`): `resolveValue()` in `/Users/dwahl/Scripts/pantoken/packages/core/src/resolve.ts`:

```ts
export function resolveValue(raw: string): string {
  const match = raw.match(REFERENCE);            // /^\{([^}]+)\}$/
  return match ? `var(${referenceToVarName(match[1])})` : raw.trim();
}
```

  Supporting utilities in the same file: `referenceToVarName()` (maps `semantic.color.background.base` → `--instui-color-background-base`, primitives → `--instui-primitive-…`), `collectLeaves()` (walks the tree to leaves), and `varName()` (builds the kebab custom-property name). This is what turns upstream references into the IR's `var(...)` values.

- **Reference back-pointer**: each `Token.refersTo` (populated by `defineToken`, see `packages/core/src/plugin.ts` and `build.ts`) gives you the single token a `var(...)` value points at.

To get a **final literal** you follow the `refersTo` / `var()` chain across the `Token[]` set until you hit a primitive whose `value` is a hex/rem literal (or a `light-dark()` you split by mode). The repo does this transitively for validation (dangling-ref checks in `validate-generated`) but does not expose a one-call "resolve to computed literal" helper — you'd implement that walk over `buildTokens()` output (or over the per-theme `generated/*.json`) using `refersTo`.

## 3. Where the hover border-color value is defined (the important part)

There is **no** `--instui-component-billboard-button-hover-border-color` token. The hover border color is set inline in the rule, and which value wins depends entirely on the theme, resolved at build time:

- **Base / rebrand:** `border-color: var(--instui-color-text-base)` → **text** color.
- **Canvas and Canvas high contrast:** the `@media (--theme-canvas), (--theme-canvas-high-contrast)` override sets `border-color: var(--instui-component-link-text-color)` → **link** color.

### How the custom media is resolved

`--theme-canvas` / `--theme-canvas-high-contrast` are custom-media aliases handled by a PostCSS plugin, not a `@custom-media` declaration in the CSS source:

**`/Users/dwahl/Scripts/pantoken/plugins/postcss/theme-custom-media/src/index.ts`**

```ts
const THEME_ALIAS = new Map&lt;string, string&gt;([
  ["--theme-rebrand", "(theme: rebrand)"],
  ["--theme-canvas", "(theme: canvas)"],
  ["--theme-canvas-high-contrast", "(theme: canvasHighContrast)"],
  ["--theme-light", "(theme: rebrand) and (prefers-color-scheme: light)"],
  ["--theme-dark", "(theme: rebrand) and (prefers-color-scheme: dark)"],
]);
```

For a given target theme the plugin (`themeCustomMedia({ theme })`):
- Drops `@media` branches that reference a non-target theme.
- Unwraps a branch into bare rules when it becomes unconditionally true for the target theme (`rule.replaceWith(...rule.nodes)`).
- Removes the `@custom-media --theme-*` declarations from output.

The build result is baked into `billboardByTheme` in **`/Users/dwahl/Scripts/pantoken/formats/components/src/generated/component-styles.ts`**, which has three keys: `rebrand`, `canvas`, `canvasHighContrast` (`billboard = billboardByTheme.rebrand`):

- **`rebrand`:** the `@media (--theme-canvas)…` blocks are stripped entirely, so hover border-color stays `--instui-color-text-base`.
- **`canvas` / `canvasHighContrast`:** the media wrappers are removed and the inner rule is emitted as a duplicate, later-source-order selector that overrides the base. For example, in the canvas string:

```css
.pfx-billboard.-clickable:hover {
  border-style: dashed;
  border-color: var(--instui-color-text-base);
}

.pfx-billboard.-clickable:hover {
    border-color: var(--instui-component-link-text-color);
  }
```

The prebuilt default-theme output is also on disk at **`/Users/dwahl/Scripts/pantoken/formats/components/generated/billboard.css`** (the `.instui-` rebrand build) and **`/Users/dwahl/Scripts/pantoken/formats/components/dist/billboard.css`** — in those the canvas overrides are gone, so hover = text.

## Modifier / state authoring convention

- **Modifiers** are chained classes with a leading hyphen on the block class: `.pfx-billboard.-clickable`, `.pfx-billboard.-size-sm`, `.pfx-billboard.-size-md`/`.-size-medium` (short + long-form aliases), `.-size-lg`/`.-size-large`. Icon modifier is an attribute-substring match on the part: `.hero[class*="-icon-"]`. Modifiers are documented via `@modifier` JSDoc tags at the top of the file.
- **States** are standard pseudo-classes chained after the modifier: `.-clickable:hover`, `:focus`, `:focus-visible`, `:active`.
- **Parts** (`.hero`, `.heading`, `.message`) are styled inside `@scope (.pfx-billboard)` using `:scope &gt; .part`, with non-scoped fallback rules duplicated above the `@scope` block for engines that don't apply `@scope`.
- **Theme-conditional styling** is authored with `@media (--theme-canvas), (--theme-canvas-high-contrast)` custom-media wrappers, resolved per theme at build time by the `theme-custom-media` PostCSS plugin.

One thing worth flagging: the `@scope` hero rules (`:scope.-clickable:hover &gt; .hero`) always use `--instui-component-link-text-color` regardless of theme, whereas the border color is theme-gated — so in the rebrand theme the hero icon turns "link" color on hover but the border turns "text" color.</result>

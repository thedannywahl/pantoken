## Phase 1 — Rewrite `packages/scaffold/src/cli.ts`

Replace the manual `parseArgs` loop with a commander-based command builder, exporting granular, independently reusable pieces (not just one opaque function), so `ai/pantoken-ai/src/cli.ts` can compose its own subcommand from the same logic instead of reimplementing it or wrapping an entire pre-built `Command`.

### New exports from `packages/scaffold/src/cli.ts`

```ts
// Re-exported for convenience so cli.ts consumers need one import, not two.
export { SCAFFOLD_PLATFORMS, isScaffoldPlatform } from "./index.ts";

/** Thrown for user-facing CLI errors (missing platform under --yes, etc.); carries an exit code. */
export class ScaffoldCliError extends Error {
  constructor(message: string, public readonly exitCode: number = 1) { super(message); }
}

/** Whether a value should be interactively prompted for: no flag/arg given, not --yes, and stdin is a TTY. */
export function shouldPrompt(value: string | undefined, opts: { yes?: boolean; isTTY?: boolean }): boolean;

export interface ResolveScaffoldTargetOptions {
  platformArg?: string;
  dirOption?: string;
  yes?: boolean;
  /** Injectable for tests; defaults to `process.stdin.isTTY`. */
  isTTY?: boolean;
}

/**
 * Resolve platform + directory: validates/prompts for platform via clack `select()` when omitted
 * on a TTY (not --yes); validates/prompts for dir via clack `text()` under the same conditions;
 * throws ScaffoldCliError with a clear message when a required value is missing non-interactively.
 */
export async function resolveScaffoldTarget(
  options: ResolveScaffoldTargetOptions,
): Promise&lt;{ platform: ScaffoldPlatform; dir: string }&gt;;

/** Runs `scaffoldProject()` wrapped in a clack `spinner()`; returns the written paths. */
export async function scaffoldWithSpinner(platform: ScaffoldPlatform, dir: string): Promise&lt;string[]&gt;;

/** Detects the invoking package manager from `npm_config_user_agent` (create-vite/create-vue technique). */
export function detectPackageManager(
  env?: NodeJS.ProcessEnv,
): "npm" | "pnpm" | "yarn" | "bun" | undefined;

/** Prints the post-scaffold "Next steps" block. See Phase 1a for the exact text/behavior decision. */
export function printNextSteps(dir: string, written: string[]): void;

/** A commander `Argument` validator for the platform positional, shared by both CLIs. */
export function validateScaffoldPlatform(value: string): string; // throws commander.InvalidArgumentError

export interface ScaffoldCommandOptions {
  /** Program name shown in help/usage. Default: "pantoken-scaffold". */
  name?: string;
  /** Exact invocation string for help examples, e.g. "npm create pantoken-app --". Defaults to `name`. */
  usageCommand?: string;
  /** Version string for `--version`. No default — callers pass their own package.json version. */
  version?: string;
  /**
   * Whether to auto-register @bomb.sh/tab completion subcommands on this Command. Default: true.
   * Set false only if this Command will be mounted as a subcommand of a larger root program that
   * wires completions itself (not used by the current design — see Phase 4 — but kept for flexibility).
   */
  enableCompletions?: boolean;
}

/** Builds the full, ready-to-parse commander Command for `pantoken-scaffold`/`create-pantoken-app`. */
export function createScaffoldCommand(options?: ScaffoldCommandOptions): Command;

/** Back-compat wrapper preserving the old call shape, now implemented via createScaffoldCommand(). */
export async function runScaffoldCli(
  argv: string[],
  options: { usageCommand: string; version?: string },
): Promise&lt;void&gt;;
```

Note: `shouldPromptForDir` is removed (renamed/generalized to `shouldPrompt`, now used for both platform and dir); this is the one deliberate breaking rename to a previously-exported-and-tested symbol, called out explicitly in the changeset and the test rewrite (Phase 5).

### `createScaffoldCommand()` shape (commander v15 + `@commander-js/extra-typings`)

```ts
import { Argument, InvalidArgumentError, CommanderError } from "commander";
import { Command } from "@commander-js/extra-typings";
import tab from "@bomb.sh/tab/commander";

const program = new Command(options?.name ?? "pantoken-scaffold")
  .exitOverride()                       // throw CommanderError instead of calling process.exit
  .configureOutput({ writeOut: (s) =&gt; process.stdout.write(s), writeErr: (s) =&gt; process.stderr.write(s) })
  .addArgument(new Argument("[platform]", `Platform to scaffold (${SCAFFOLD_PLATFORMS.join("|")}; "html" is an alias for "components")`).argParser(validateScaffoldPlatform))
  .option("-d, --dir &lt;path&gt;", "Target directory (defaults to \".\"; prompts interactively on a TTY if omitted)")
  .option("-y, --yes", "Never prompt; fail with an error instead of prompting for a missing platform or directory", false);

if (options?.version) program.version(options.version, "-v, --version");

program.action(async (platformArg, opts) =&gt; {
  const { platform, dir } = await resolveScaffoldTarget({ platformArg, dirOption: opts.dir, yes: opts.yes });
  const written = await scaffoldWithSpinner(platform, dir);
  for (const path of written) console.log(`✓ wrote ${path}`);
  printNextSteps(dir, written);
});

if (options?.enableCompletions ?? true) tab(program, { completionCommandName: "completion" });
return program;
```

Key precision points:
- **Platform validation happens at commander's argument-parse layer** via `validateScaffoldPlatform` (an `Argument.argParser`), not `.choices()` — `.choices()` can't be used because `isScaffoldPlatform("html")` must pass even though `"html"` is an alias not in `SCAFFOLD_PLATFORMS`. The validator message becomes commander's own `error: command-argument value '...' is invalid for argument 'platform'. &lt;our message&gt;` format — this is a real, user-visible wording change from today's `Unknown platform "...".` (see Phase 5 for the test-contract implication).
- **A second stray positional (e.g. `pantoken-scaffold react extra`) is now rejected by commander itself** ("too many arguments") since only one `[platform]` argument is declared — replaces the old `Unknown option "extra".` message with commander's own wording. This is a deliberate, acceptable behavior change (still fails clearly, just different text).
- **`.exitOverride()` + `.configureOutput()`** is the standard, well-documented commander pattern for making a Command safe to `parseAsync()` from a library context and for unit-testing without a real `process.exit` — it throws `CommanderError` (carrying `.exitCode` and `.code`, e.g. `"commander.helpDisplayed"`, `"commander.version"`, `"commander.invalidArgument"`) instead of exiting or bypassing mocked I/O.
- **`--yes`/`-y`**: forces `resolveScaffoldTarget` to skip both prompts; if platform is still missing, it throws `ScaffoldCliError('Missing required argument "platform". Expected one of: ...')`, which the caller (`runScaffoldCli`, see below) reports the same way as any other user-facing error.

### `resolveScaffoldTarget` internals (the reusable prompt flow)

- Platform: if `platformArg` is given, it's already been validated by commander's argParser by the time this runs (when called from `createScaffoldCommand`); when called from `ai/pantoken-ai`'s own hand-built subcommand (Phase 4), `resolveScaffoldTarget` must **also** validate an unvalidated `platformArg` itself (since that caller may not run it through commander's argParser) — so `resolveScaffoldTarget` should call `isScaffoldPlatform`/throw its own `ScaffoldCliError` defensively even if the argument theoretically arrives pre-validated. This makes it safe to call from either context.
- If `platformArg` is omitted:
  - `shouldPrompt(platformArg, { yes, isTTY })` false → throw `ScaffoldCliError` (missing platform, non-interactive).
  - true → `@clack/prompts` `select({ message: "Which platform?", options: SCAFFOLD_PLATFORMS.map((p) =&gt; ({ value: p, label: p })) })`. On `isCancel(result)` → `cancel("Cancelled.")`, throw `ScaffoldCliError("Cancelled.", 1)`.
- Directory: same `shouldPrompt` gate; on true, `text({ message: "Project directory", placeholder: ".", defaultValue: "." })` (clack returns the default automatically on empty Enter — replaces the old manual `.trim() || "."`). Same cancel handling.
- On `--yes` with `--dir` omitted: silently defaults to `"."` (unchanged from today's non-TTY default) — `--yes` does **not** require `--dir`, only `platform`.

### 1a. The "next steps" / package-manager-detection fork — **flagging for your decision**

**Finding:** the scaffolded projects' generated `package.json` files (checked `packages/scaffold/generated/scaffolds.ts`) never depend on `vite-plus`/`vp` — `vp install` is pantoken's own convention recommendation, not something tied to the scaffolded project itself. Today's message is a static string:
```
Next steps:
  cd &lt;dir&gt;
  vp install   (or npm/pnpm/yarn/bun install)
```
**Finding (test-breaking risk):** `packages/create-pantoken-app/tests/index.test.ts` and `packages/scaffold/tests/cli.test.ts` both assert `output.toContain("vp install")` on the output of the **spawned child-process bin**, run under this monorepo's own pnpm-driven test runner — meaning `process.env.npm_config_user_agent` is already set to `pnpm/...` for that child process. If `detectPackageManager()` is used to *replace* the printed line, these tests would see `"pnpm install"` instead and fail.

Two options — **recommend Option A as the default; Option B needs explicit sign-off** since it changes visible output and requires updating 3 existing test assertions:
- **Option A (recommended, zero test breakage):** implement `detectPackageManager()` and export it, but do **not** wire it into `printNextSteps()`'s primary line yet. Keep printing the exact current static text. This satisfies "investigate" without a behavior change; `detectPackageManager` becomes available for `ai/pantoken-ai` or a later follow-up to use.
- **Option B (behavior change):** `printNextSteps` prints `${detectPackageManager() ?? "vp"} install` as the primary line, falling back to today's full static text only when detection fails. Requires updating the two "vp install" assertions in `packages/scaffold/tests/cli.test.ts` and one in `packages/create-pantoken-app/tests/index.test.ts` to either force-clear `npm_config_user_agent` in the test's `env` before spawning, or assert `/install/` instead of the literal string.

Plan proceeds with **Option A**; flip to Option B only if you confirm you want the behavior change.

### Backward-compatible `runScaffoldCli`

```ts
export async function runScaffoldCli(argv: string[], options: { usageCommand: string; version?: string }) {
  const program = createScaffoldCommand({ name: options.usageCommand, usageCommand: options.usageCommand, version: options.version });
  try {
    await program.parseAsync(argv, { from: "user" });
  } catch (err) {
    if (err instanceof CommanderError) {
      if (err.code === "commander.helpDisplayed" || err.code === "commander.version") return; // matches old "--help returns without exiting" contract
      process.exit(err.exitCode);
    }
    if (err instanceof ScaffoldCliError) {
      console.error(err.message);
      process.exit(err.exitCode);
    }
    console.error("Error scaffolding project:", err instanceof Error ? err.message : err);
    process.exit(1);
  }
}
```
This is what both `packages/scaffold/bin/pantoken-scaffold.mjs` and `packages/create-pantoken-app/bin/create-pantoken-app.mjs` continue to call — **both bin files need zero or near-zero changes**. The only optional addition: pass a `version` read from each package's own `package.json` via `import pkg from "../package.json" with { type: "json" }` (Node 22 JSON import attributes — safe given `engines.node &gt;=22.18.0`), so `--version` reports the correct package version per binary.

### New file: `ai/pantoken-ai/src/cli.ts`

Mirrors `packages/scaffold/src/cli.ts`'s pattern: exports a builder + a run wrapper.

```ts
export interface AiCommandOptions { name?: string; version?: string }

export function createAiCommand(options?: AiCommandOptions): Command {
  const program = new Command(options?.name ?? "pantoken-ai")
    .exitOverride()
    .configureOutput({ writeOut: (s) =&gt; process.stdout.write(s), writeErr: (s) =&gt; process.stderr.write(s) });
  if (options?.version) program.version(options.version, "-v, --version");

  program
    .command("init")
    .description("Write pantoken's agent assets into a repo")
    .addOption(new Option("-t, --tool &lt;tool&gt;", `Tool (${["all", ...AGENT_TOOLS].join("|")})`).default("all").choices(["all", ...AGENT_TOOLS]))
    .option("-d, --dir &lt;path&gt;", "Target directory", ".")
    .action((opts) =&gt; {
      const written = installAgentAssets(opts.tool, opts.dir);
      for (const p of written) console.log(`✓ wrote ${p}`);
    });

  program
    .command("scaffold")
    .description("Scaffold a starter project (via @pantoken/scaffold) and install agent assets into the same directory")
    .addArgument(new Argument("[platform]", `Platform (${SCAFFOLD_PLATFORMS.join("|")})`).argParser(validateScaffoldPlatform))
    .option("-d, --dir &lt;path&gt;", "Target directory (prompts interactively on a TTY if omitted)")
    .option("-y, --yes", "Never prompt", false)
    .addOption(new Option("-t, --tool &lt;tool&gt;", `Agent tool (${["all", ...AGENT_TOOLS].join("|")})`).default("all").choices(["all", ...AGENT_TOOLS]))
    .action(async (platformArg, opts) =&gt; {
      const { platform, dir } = await resolveScaffoldTarget({ platformArg, dirOption: opts.dir, yes: opts.yes });
      const scaffoldFiles = await scaffoldWithSpinner(platform, dir);
      const assetFiles = installAgentAssets(opts.tool, dir);
      for (const p of [...scaffoldFiles, ...assetFiles]) console.log(`✓ wrote ${p}`);
      printNextSteps(dir, scaffoldFiles);
    });

  tab(program, { completionCommandName: "completion" }); // wired once, on this program's own root
  return program;
}

export async function runAiCli(argv: string[], options?: AiCommandOptions): Promise&lt;void&gt; {
  // same exitOverride/CommanderError/ScaffoldCliError catch pattern as runScaffoldCli
}
```

- Note the `scaffold` command here uses `.command("scaffold")` + a manually attached `Argument` (rather than the string-shorthand `.command("scaffold &lt;platform&gt;")`) specifically so `validateScaffoldPlatform` (imported from `@pantoken/scaffold/cli`) can be attached via `.argParser`, keeping a single source of truth for the platform-validation error message across all three CLIs.
- `resolveScaffoldTarget`, `scaffoldWithSpinner`, `printNextSteps`, `validateScaffoldPlatform` are all imported from `@pantoken/scaffold/cli` — this is the literal reuse the task calls for: the platform-select/dir-text/spinner UI runs unmodified, then `installAgentAssets` runs after.
- `printNextSteps` is now shared verbatim across all three CLIs, which changes `pantoken-ai scaffold`'s old output from `"\nNext: cd ${dir} &amp;&amp; npm install (or pnpm/yarn/bun install)"` to the same `"Next steps:\n  cd ...\n  vp install ..."` block used by `pantoken-scaffold`. **This is a deliberate, user-visible behavior change for `@pantoken/ai`**, worth its own line in that package's changeset.
- Completions (`tab(program, ...)`) are wired **exactly once**, on `ai/pantoken-ai`'s own root `Command`, covering both its `init` and `scaffold` subcommands. `createScaffoldCommand()` (from `@pantoken/scaffold/cli`) is deliberately **not** mounted wholesale here via `addCommand()` — reusing granular functions instead avoids double-registering a nested `completion` subcommand and gives room for the `--tool` option that `createScaffoldCommand()` doesn't know about.

## 5. Are these really design tokens?

Yes. Both are token systems that **compose base tokens into composite custom properties**: elevation is a shadow scale built from `--instui-color-drop-shadow-*`; focus-outline is a themed ring-variable set built from `--instui-component-shared-tokens-focus-outline-*` and `--instui-border-radius-md`. They exist as bespoke builder functions (not `defineDeclaration`) only because (a) their output is a `:root` token block rather than modifier classes, and (b) focus additionally emits ring rules on a second selector. The doc comments literally call them `@declaration` records.

Relevant types:
- `CssRecordKind` (from `@cssdoc/core`) — includes the `"declaration"` kind; both `elevation` and `focus` set `kind: "declaration"`.
- `Definition` (`formats/components/src/lib/define.ts`) — `{ name, kind, rules(prefix), css(options) }`; `defineDeclaration` is the wrapper these two deliberately bypass.

- **Light (matches your plan):** move only the two pure `[name,value][]` builders down to `@pantoken/tokens` (or `@pantoken/utils`); have `@pantoken/css` emit them as a foundation section, delete the proposed `foundation.css`, and repoint `web-components`/`pendo`/`components` at the shared builders.
